# Agent 引导多轮模拟

这是一套由维护者控制模拟用户、独立 subagent 实际执行的行为验收，不是字符串命中测试，也不是已校准的模型基准。全部人物、公司、项目、JD 和消息均为合成材料。

首次执行见 [2026-10-15 运行报告](runs/2026-10-15/report.md)。`cases.json` 保存五个基础场景；本轮新增的“暂缓不等于下次优先”回归点单列在报告与 D9 用例中，不修改首次验收标准掩盖问题。

## 执行方式

1. 从开发源码构建当前 npm 产物，再运行 `node scripts/prepare-agent-simulation.mjs --out <空的绝对临时目录>`。生成独立工作区与 runtime；不接触真实个人资料、不联网查询企业、不发送消息、不投递。
2. 每个测试 Agent 使用全新上下文（`fork_turns: none`），只收到该工作区路径、环境限制与 cases.json 中的 opening。不得读取本目录、其他工作区、隐藏后续回答或评审结论。
3. 协调者按实际追问，从 cases.json 的 user_facts 提供相关回答；不把全部答案一次给出，不告诉被测 Agent 应如何通过。未涉及的事实仍隐藏。实际发送的措辞及每轮回复完整保存，不能把预设脚本冒充实际对话。
4. 每轮检查并快照来源、事实、问题、维护清单、progress、state、岗位与模拟记录。新 Agent 续接只看工作区，不接收上一位 Agent 的聊天记录。
5. 评审依据实际对话和文件内容；脚本校验仅作结构佐证。区分通过、部分通过、失败、未执行、环境无效。不能用 Agent 自评、篇幅或写了几个文件代替质量判断。
6. 只针对已观察到的失败修改方法。修正后重建包，在新的隔离目录复测；保留第一次结果。没有重复试验或不同模型时，不声称得到稳定通过率。

在每轮 Agent 结束后运行 `node scripts/snapshot-agent-simulation.mjs <运行目录> <case-id> <检查点名>`，固定当轮产物并独立运行结构检查。需要续接／草稿分支时，在 assets 暂停后运行 `node scripts/fork-agent-simulation.mjs <运行目录> assets handoff`（或 draft）；排除上轮聊天回放、执行脚本和 Git 历史，仅保留正常工作区文件。之后启用新的 `fork_turns: none` Agent。case 定义中的事实可按实际提问顺序提供，微小补充先写入定义；记录调整原因，不能修改标准来迁就被测结果。

## 环境边界

本套测试运行真实 career CLI 和随包 Skills。为避免重复下载，临时 runtime 采用当前 npm 打包产物，依赖链接到开发环境已安装的 node_modules；工作区 npm 入口指向这个只读 runtime。这个替代不验证操作系统安装、注册、远端同步、网络检索、桌面 GUI 或 PDF 导出。测试 Agent 可写自己的工作区，禁止修改 runtime 和其他目录，不使用全局个人 Skills。

`cases.json` 是协调者与评审可见的场景定义，**不能放进被测工作区或安装包**。`runs/` 保存合成对话、结果和关键产物证据；完整快照留在临时执行目录。源文件哈希记录当前脏工作树的真实版本，不能仅用 Git HEAD 代表本轮方法。

本套由用户于 2026-10-15 授权使用 subagent 执行。模型继承当前会话配置，不人为指定另一个模型；如果工具不提供精确模型 ID，就记录不可见。协调者同时充当模拟用户和评审，存在评审偏差；这属于首轮受控行为验收，非盲测或统计效果证明。
