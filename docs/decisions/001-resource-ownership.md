# 001：任务资源随 Skill，开发上下文随仓库

日期：2026-10-12。状态：已采纳。

## 背景

career 需要让 Agent 在初始化后持续完成求职任务，也要方便开发者接手。原先简历模板和流程分散在公共 resume/ 与 Skill 中，使同一任务需要跨多处查找方法资料。

## 决定

1. 求职任务的执行方法、参考资料、模板、任务示例与专用脚本放在负责该任务的 Skill 内。SKILL.md 是入口，按需链接随包资源。
2. docs/ 保存开发所需的架构、共享数据契约、开发说明、调研与项目上下文。长期决定在 decisions/，当前进度与交接入口在 context.md。
3. 用户自己的独立目录保存真实资料、私人上下文和任务产物。开发仓库内的 workspace/ 仅作被忽略的本地目录；正式初始化不要求克隆源码仓库。模板本体留在 Skill，实例化的记录写入用户目录。
4. AGENTS.md 保持全局规则与导航职责。跨模块契约由仓库统一维护，Skill 引用，不各自复制一份 schema。
5. 仓库级上下文模板保留在 templates/context/；通用数据工具保留在 scripts/；开发回归用的完整虚构工作区保留在 examples/。这些资源服务跨模块协作和开发验收。

## 影响

移除公共根 resume/，将事实、母版、版本及平台模板归入三个 Skill；数据格式与更新边界合并到 docs/data-model.md。初始化、校验与留存同步读取新位置。用户工作区不迁移，现有记录、ID 和冻结版本格式不变。

独立分享 Skill 时携带完整目录，可以按随包方法和模板生成草稿；career 的数据校验、留存和完整契约仍依赖本仓库。新增求职能力沿用这一归属规则。
