# 简约研发：固定间距与自然分页（2026-10-19）

## 纠正上一版

上一候选为了让末页更满，主动把前页条目移动到末页；分页后又按空白大小增加段间距。结果是前页产生可避免的大片空白，同类经历的间距在不同页面不一致。该候选不采用，删除其自动压缩、短尾整块绑定及最后两页均衡算法。

## 当前策略

1. 全文使用一套固定间距：页头后 5mm、章节前 4mm、章节标题后 2mm、条目后 3.5mm、段落间 1.5mm、要点间 1mm、资料网格行距 2mm。紧凑密度是用户选定的另一套全篇固定值，不根据内容量自动切换。
2. 按原文顺序自然排满；标题、岗位、技术栈作为开头跟随至少两行正文，长段落／要点按行续页。段落两端至少两行，不绑定整个长项目或最后两条要点。
3. 续页显示条目名称及“（续）”。不在项目之间画横线，保留章节分隔线。
4. 最后一页自然结束，允许短于前页；不倒移内容、不拉大行间或段间距、不缩字体来凑页。手动分页优先。
5. 预览、离线 HTML 和 PDF 使用同一 Paged.js 流程，字体／图片就绪后仅排一次；engineering 跳过旧版分页后间距补偿。源资料、项目顺序、字号与正文行高不变。

## 回归

生产 PDF 专项使用虚构内容验证长短项目、长段落／要点、手动分页、照片与工作经历、紧凑密度和自定义字号。追加后续项目不能改变之前已经排满的页面；有无后续手动分页，前面相同工作要点的间距必须一致。逐项核验文字完整和顺序、续页名称及页脚边界。序列化测试保证预览函数不依赖服务器闭包。

私人简历仅在仓库外只读构建、导出和核验，不改写用户包与旧快照。最终验证结果见项目上下文。后续桌面发布状态见 [alpha.18 发布记录](../releases/desktop-0.3.0-alpha.18.md)。
