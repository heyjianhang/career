# 本机工作区与设置

工作区是一个普通文件夹，包含求职偏好、个人经历、岗位、简历及 Agent 协作记录。每份工作区独立保存，可以使用不同名称；网页从同一份文件读取，CLI 和 Agent 也操作这个目录。

## 页面操作

侧栏顶部的按钮用于折叠。收起后显示 `c.`，悬停或键盘聚焦时变为展开图标；各导航项在右侧显示名称。求职看板、简历、我的资料共用尺寸、间距与图标。底部是设置。

在“设置 → 工作区”中：

- **创建工作区**：填写名称、选择父目录，显示将创建的完整路径，确认后创建并打开。只接受新文件夹，已有同名文件夹不会覆盖；工作区不能嵌套，也不能建立在程序安装目录内。
- **打开已有工作区**：通过文件夹列表或完整路径选择含 `career.json` 的目录。普通文件夹不会被自动初始化。
- **最近使用**：切换之前使用的目录。文件夹被移动后会显示“重新定位”，手动选择新位置后替换本机记录。
- **改名**：修改显示名称，保存到 `career.json.name`；不移动文件夹，不影响岗位和简历的关联。老目录没有 name 时使用文件夹名。
- **打开文件夹／复制路径**：在系统文件管理器中定位，或将路径提供给 Agent。

创建会安装用户 AGENTS.md、八个用户 Skills、资料目录与配置，沿用现有初始化规则。用户在 Agent 软件中打开这个文件夹，再读取 AGENTS.md 继续选择是否同步、收集资料等步骤。创建不注册账户、不自动启用 GitHub 同步。

## 会话和保存边界

每个打开的工作区由独立的本机端口提供服务，同一个目录在当前进程里复用会话。切换只导航到目标地址，原标签页始终绑定原来的目录；不会把旧页面的保存写入新目录。停止主预览进程时一起关闭这些服务。

简历编辑器有未保存内容或正在保存时，切换和创建会被拦住。关闭设置、完成保存后再继续；只是打开设置不会离开编辑器。

本机最近目录记录默认位于用户主目录的 `.career/workspaces.json`。它包含绝对路径和显示名，不放进求职资料仓库；`CAREER_LOCAL_SETTINGS` 可将该记录指向指定文件，开发和自动测试使用独立临时文件。不存在的记录不静默删除，记录损坏也不自动重置。

网页创建的目录复用当前已运行的 CLI，不在后台下载另一版包：`.local/runtime.json` 记录本机 Node 和 CLI 位置，受 Git 忽略；`npm run career -- <命令>` 通过 `.career/run.mjs` 调用。换机后如果该本机路径失效，启动器会使用工作区 `node_modules` 中安装的包；尚未安装时提示执行 `npm install --ignore-scripts`。独立恢复仍遵循工作区 package.json 锁定的版本。开发版的新能力需随正式包发布后才能在其他机器安装使用。

目录浏览和修改需要当前页面的会话凭据与同源请求，服务只监听 127.0.0.1；不提供远程文件管理。文件夹选择器显示子目录，不展示其他文件内容，不跟随符号链接。不同工作区不能复用彼此的写入凭据。

## 开发验证

- `npm test`：创建、重名保护、嵌套／路径拒绝、配置保留、CLI 启动器、目录移动、并发本机记录、HTTP 校验、工作区隔离与服务关闭。
- `npm run test:workspaces`：三页侧栏、悬停标签、创建／打开／改名／切换、重新定位、未保存保护、键盘操作及 320–1440px。
- `npm run test:package`：真实安装包启动服务、网页创建第二份工作区，以及从该工作区调用 CLI。

这是当前本地开发能力，尚未发布到 npm。另有 [桌面开发预览](desktop.md)，使用随包 CLI 和系统文件夹选择器；桌面最近列表放在应用的 userData 中，工作区入口为 `.local/career` 或 `.local/career.cmd`。桌面首次进入工作区默认展开侧栏，后续尊重同目录内的手动收起选择；窄窗口仍自动收起。托盘提供显示／隐藏窗口、切换工作区和退出；关闭窗口仍退出，不包含开机启动。

## 云同步与从仓库恢复

开始页和工作区设置增加「从仓库恢复」，填 GitHub 私人仓库与新目录。空仓库初始化；已有 main 检查路径／附件后恢复并校验。不会覆盖已有文件夹。桌面复用内置 CLI，浏览器复用本机安装。

侧栏「云同步」提供更新、同步、自动同步和环境检查。缺 Git／GitHub CLI 显示官方安装入口，重新检测会搜索常见 macOS／Windows 安装位置；它们是可选同步依赖，不阻塞本机资料。账号在 GitHub 官方设备登录页完成，career 不保存密码或令牌。首次提交缺身份时在版本署名补齐，只写当前仓库。

- `sync update`：先保存本地修改，再安全合并远端，不上传。
- `sync run`：保存、获取、合并、上传；无内容变化不新增提交。
- `sync overview`：本机状态、最近结果、冲突提交和文件，不联网。
- `sync preferences --automatic on|off --interval 5`：本机设置，默认关闭，1–60 分钟。
- `sync environment`：检测依赖和登录，返回官方安装入口。

自动同步由每个工作区服务管理，不在浏览器 Tab 中执行。设置和结果在忽略的 `.local/sync.json`，新设备默认关闭。开启后初次先更新，文件稳定 30 秒再操作，之后定期同步；软件或预览进程退出停止。网络错误退避重试，冲突／异常资料暂停，手动成功后恢复。资料更新提示重新载入，未保存的编辑通过原有退出保护及版本冲突检查保留。

合并在临时隔离 checkout 校验，成功才快进本机；冲突记录两侧提交与文件，正文不写冲突标记。并发推送由 Git 拒绝过期更新，不强推。单文件上限 25 MiB，受管路径与 history save 一致。数据更新不会升级工具版本。

实现：src/workspace/sync.ts、sync-api.ts、sync-environment.ts；UI／CLI 共用引擎，保留旧 sync pull／push 兼容命令。环境来源：[Git 官方安装](https://git-scm.com/install/)、[GitHub CLI 登录](https://cli.github.com/manual/gh_auth_login)。
