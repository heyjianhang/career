# Agent 引导与推进规则

这是个人工作区的共同协作方法。入口是工作区 `AGENTS.md`；实际任务按对应 Skill 执行。大阶段记在 `context/progress.md`，当前对话断点记在 state。文件由宿主 Agent 主动读写，规则不会自动执行；CLI 不替 Agent 判断资料深度。

## 先读大阶段，再接着当前一项

`context/progress.md` 是跨会话的阶段总账：本轮范围、当前大阶段、各阶段状态、转段依据与范围变化历史。它与两份已有文件分工如下：

| 文件 | 回答的问题 | 不重复保存 |
| --- | --- | --- |
| progress | 本轮做到哪，大阶段为何可继续，哪些还没完成？ | 每个项目的整张状态表与详细正文 |
| maintenance | 哪条经历整理到什么程度、母版需不需要更新？ | 整条路线的阶段历史 |
| state | 当前停在哪一项、下次具体接着问什么？ | 另一份阶段总账或完整履历 |

默认路线是：盘点与范围 → 逐项访谈与资产沉淀 → 资产核对与缺口处理 → 母版表达 → 成品使用 → 持续积累。先核对已有文件，不能按文件存在自动打勾。缺少 progress 时用 `workspace init` 补骨架，再按实际材料填写；旧资料不覆盖，也不能默认视作全部已完成。

阶段状态使用待核对、未开始、进行中、等待补充、本轮完成、暂缓、不在本轮。它描述本轮约定范围，不是永久完成度。只整理资产时，母版和成品不在本轮；只打开旧简历时可以直接进入成品；岗位任务可独立进行，关联到本轮范围，不强迫履历全部重走。

每次重要转段先核对该范围下的实际产物与剩余项，再在 progress 写清依据。普通回答更新正文、条目及下一问即可，不追加一条冗长阶段日志。新事实或纠正只重开受影响阶段及依赖表达，保留过去完成的范围和日期。

## 先确定这次要做到哪里

从用户请求、`context/state.md` 和实际文件确定本轮终点，已明确的选择不再问。例如“详细整理这个项目”做到事实可复用；“整理后生成简历”还需母版、内容包和可访问的页面；“导出已有简历”直接处理成品；“收藏这个岗位”先入库，不以完整简历为前提。只有歧义会改变工作范围时才补问。

开始只说明当前主题与下一步，不把整条路线讲成操作手册。恢复时先读状态及其所指正文；用户说“继续”通常是继续当前未完成项，不是进入下一个阶段。

## 当前工作单元

履历访谈默认一次深入一段工作或项目，岗位任务默认一个岗位中的一个问题。用户同时提供多项时都保存，列出已知范围，再选当前项深入；其他项保留待维护。用户主动换话题时保存当前断点，再跟随新意图。

每轮采用这个短循环：

1. **接住信息**：读已有材料，区分新事实、补充、纠正与推断；先保存能确定的内容。
2. **判断缺口**：按当前类型的专家方法，找最影响理解的一处缺口。不是按模板顺序逐字段提问。
3. **继续追问**：通常一个主问题，可带紧密相关的小提示；围绕刚收到的回答追问，避免突然跳到下一段经历、排版或导出。
4. **回写并展示**：保留具体过程、分工和来源，再给用户看一段简明整理。未回答的问题继续保留，不能当作认可。
5. **检查是否可转段**：满足下面的条件再衔接；已有整套任务授权时直接继续，不逐步索要许可。

文件写入失败时仍保留当前问题，说明哪些未保存。文件存在、字段齐全、`valid:true`、篇幅长或用户只回“嗯”都不能证明资料已整理充分。

## 四种进展不要混用

| 进展 | 实际含义 | 还不能据此声称 |
| --- | --- | --- |
| 已记录 | 已有来源与部分事实，可能只是“参与过某项目” | 该项目已整理完 |
| 本轮已整理 | 当前限定范围可被另一位 Agent 理解，满足类型标准，已保存并展示，关键缺口已处理 | 所有经历齐全、事实获得外部证实 |
| 母版可复用 | 已把成熟事实组织成有来源的表达，索引与可读正文一致 | 已生成可用成品或投递过 |
| 成品可用 | 内容包已校验，实际页面／导出文件按请求检查过 | 所有事实都已深入访谈、旧 PDF 已自动更新 |

条目沿用 [维护清单的状态](../.agents/skills/career-intake/references/maintenance.md)，宏观阶段由 progress 记录；两者不互相替代，也不增加新的阶段数据库。

## 从经历整理进入母版

对当前项目／工作，先核对实际正文能否回答：它为何发生、本人负责什么、具体怎样推进、交付到哪一步、依据在哪里。重要经历要有能展开解释的过程或案例；“负责开发／推进／优化，效果良好”仍需追问。具体标准看 [项目访谈](../.agents/skills/career-intake/references/project.md) 或 [任职访谈](../.agents/skills/career-intake/references/employment.md)。

同时核对本轮范围：用户要求逐项详细整理时，当前项不能因为已经能写一句简历就收尾；用户要求整份简历时，不能把只问过一个项目当成全部经历已覆盖。已知未处理项、暂缓项和不适用项在维护清单分别保留。

默认先完成 progress 中本轮纳入范围的资产整理与核对，再形成母版。单条完成后若仍有本轮纳入的任职或项目未深入，继续整理它们；不以“先产出一点”为由自动转段。用户已约定分批交付、明确先要快速草稿或主动跳过时可以例外，记录范围和原因，保留未完成阶段与恢复入口，不强迫补全。

生成草稿不改变事实的维护状态。缺量化收益、照片、链接、精确到日的日期不天然阻塞；主要贡献归属或成果真实性冲突则不能写成确定成果。项目由 [career-project](../.agents/skills/career-project/SKILL.md) 深入，任职由 [career-employment](../.agents/skills/career-employment/SKILL.md) 整理，写法见 [职业资产方法](career-assets.md)。

可以这样自然衔接：“这个项目的分工、关键处理过程和实际交付都已记下；上线后的效果还没统计，先不写收益。接下来把这一段整理成母版。”不能只说“资料足够了”而没有对应内容。

## 从母版进入成品

按 [resume-master](../.agents/skills/resume-master/SKILL.md) 检查当前范围内的正文、来源、未解决项和手改，再按 [resume-tailor](../.agents/skills/resume-tailor/SKILL.md) 生成统一内容包。没有 JD 可以生成通用版；平台稿由工具映射，不额外编造四份经历。只导出、换样式或打开已有成果时不重走访谈。

用户要求整套交付，做到实际可访问的页面或实际导出的文件；尚有缺口的成品可以是限定范围的草稿，不能用页面已经打开来宣布“经历已全部整理好”。

## 岗位与面试是可独立进入的分支

按 [career-board](../.agents/skills/career-board/SKILL.md) 先保存岗位原文与来源，再分别做公司分析、岗位匹配、准备或模拟。记录判断和依据，未知部分留给后续核对。收录岗位不自动投递，分析不自动代表用户打星，模拟不改变真实面试进度。公司与匹配分析保持自由 Markdown，不强迫填满固定章节。

## 断点与交接

每轮有实质信息时保存事实／分析，再更新详细状态；范围或阶段变化时更新 `context/progress.md`，最后更新 `context/state.md`。state 保持简短，至少让下一位 Agent 找到：

- 本轮目标与终点；当前对象的稳定 ID、阶段和文件路径。
- 已实际保存什么，当前尚未完成什么；证据在正文和来源中，不重复抄写。
- 下一次要接着问的具体问题（或问题 ID）及原因，谁需要回答。
- 满足什么条件可转入下一步；用户主动暂缓／改方向的决定。

区分用户明确指定的续接顺序与 Agent 建议。“某项下次再讲”只确定本次暂缓，不自动表示下次优先，也不表示当前项目已结束。顺序未指定时保留当前项断点；如建议换到另一项，写明是建议及原因，不写成用户已决定。下次“继续”按已确认的断点恢复，新的用户选择优先。

收尾可以只说“已保存什么 + 当前还差什么 + 一个下一步”。不在用户每次回答后重复整个路线图。重要节点按 [career-git](../.agents/skills/career-git/SKILL.md) 保存本地版本，远程同步遵循已选方式与已有授权。
