# 浏览器岗位收藏扩展

在 Chrome 或 Edge 打开一个岗位，点击 **career · 岗位收藏**，核对内容后收藏或复制给 Agent。采集记录按平台展示，可以搜索、查看原文、点击职位标题回到招聘页面。

当前为仓库内的独立扩展 `0.1.0`，尚未上架浏览器商店，也没有随桌面安装包分发。扩展不依赖 Node、桌面应用或本地服务运行；从源码构建时需要 Node.js 22+。

## 加载开发版

在仓库根目录运行：

```sh
npm run build:extension
```

生成 `build/browser-extension/` 和 `build/career-job-clipper-0.1.0.zip`。

1. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，启用“开发者模式”。
2. 选择“加载已解压的扩展程序”，选中 `build/browser-extension` 文件夹。拿到 ZIP 时先解压，选择包含 manifest.json 的那一层文件夹。
3. 把 **career · 岗位收藏** 固定到工具栏，打开岗位详情后点击图标。

更新时重新构建，在扩展管理页点击“重新加载”。同一个扩展 ID 下保留原有记录；移动加载目录可能改变 ID。卸载扩展、清除浏览器资料或换浏览器不会自动保留记录，操作前导出 Markdown。

## 使用流程

1. **打开具体岗位。** 优先用单个岗位的详情页；列表内嵌详情只有识别到独立岗位链接后才能收藏。验证页面由用户完成验证后再采集。
2. **核对采集结果。** 展示职位、公司、地点、薪资、经验、学历、来源链接、采集时间和岗位原文。页面提供福利或公司介绍时一并提取，缺失时留空。特殊字体导致无法读取的薪资会留空并提示核对。
3. **收藏或复制。** “收藏岗位”只写当前浏览器。“复制给 Agent”先保存，再复制入库指令及资料；剪贴板失败时仍保留收藏，可以下载 Markdown。
4. **交给 Agent。** 在已经打开 career 个人工作区的 Agent 对话中粘贴。Agent 读取工作区 AGENTS 和 career-board Skill，通过现有 CLI 查重、登记，写入 job.md，再按用户目标进行分析。

采集记录只有“已收藏／已复制”，没有自动标成“已入库”。复制本身不证明 Agent 已创建卡片。第一版不直接连接桌面应用，不自动投递或发消息。

## 平台适配

| 来源 | 读取范围 | 需注意 |
| --- | --- | --- |
| BOSS 直聘 | 独立岗位页、可识别的内嵌详情正文与链接 | 特殊字体薪资需手动核对；猎头公司不能代替用人公司 |
| 猎聘 | 独立岗位页的职位介绍、公司、薪资、地点、经验与学历 | 公司介绍只包含页面已展开内容 |
| 智联招聘 | 独立详情及含独立链接的内嵌详情 | 短正文会提示核对，不自动补写 |
| 前程无忧 | 独立岗位页的职位描述、公司、福利与基本要求 | 遇到访问验证先由用户完成 |
| 官网／其他 | 唯一主标题与可识别的职位描述区域 | 通用提取不保证识别所有网站；可以选中正文采集或手动粘贴 |

平台可能更改页面。采集结果可编辑，不把推荐职位、聊天内容或整个页面当作 JD；无法识别正文时留空提示。仅根据页面已加载的文字提取，未显示或折叠的内容需先在网站展开。选中文字后再点扩展，会以选中文字作为本次正文。

## 原文、重复与交接

- 以清理后的独立岗位链接，或平台加岗位 ID 查重；同公司不同岗位各自保存。
- 再次收藏同一岗位，明确选择查看已有记录或用本次内容更新。记录修改使用修订号检查，防止两个窗口互相覆盖。
- 第一次采集快照单独保留；后续手动校对的内容用于复制给 Agent。单条和全量 Markdown 导出同时包含首次快照。
- 招聘网页的公司介绍属于来源陈述，不等于公司研究结论。复制内容将网页材料与用户指令分开，Agent 仍须核验来源和事实。
- 新岗位的交接 JSON 只含公司、职位、地点、薪资、来源和“尚待分析”的概况，不替用户评分，不捏造已投递状态。已有岗位由 Agent 核对更新，保留原有评分、分析和用户修改。

扩展的内部记录格式为 `career-job-clip/v1`，存入 chrome.storage.local。它是浏览器采集暂存，不替代个人工作区的岗位文件夹；也不参与工作区 Git 同步。现有[岗位工作区契约](opportunities.md)不变。

## 权限与边界

权限只有 activeTab、scripting、storage、clipboardWrite。点击扩展时取得当前标签页的临时访问权，在隔离环境读取可见 DOM；没有所有网站的常驻权限，没有后台轮询、Cookie 访问、登录状态读取或招聘站私有接口请求。收藏数据不上传外部服务。

后台只接受扩展自身页面的消息，网页不能调用记录管理。原文以纯文本显示。链接只接受 HTTP(S)，常见追踪及鉴权参数从保存链接中去除；支持平台的详情链接只保留路径。

存储接近 8 MiB 时拒绝继续写入并提示导出，不自动删除旧记录。Markdown 导出用于留存与 Agent 阅读，暂不提供导入恢复按钮。

实现参考：[Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)、[Scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting)、[Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)。

## 开发验证

```sh
npm test
npm run test:extension
npm run check:docs
npm run check:example
```

业务测试在 tests/job-clipper.test.mjs，涵盖链接清理、必填校验、去重、修订冲突、首次原文、存储失败、复制状态以及真实 career CLI 的合成岗位入库。浏览器测试在 tests/job-clipper-browser.mjs，使用临时 Chromium 配置和合成页面，加载实际构建产物，验证字段提取、持久化、搜索筛选、导出和窄屏；不使用用户登录资料。

2026-10-15 已人工读取四个平台的真实岗位页结构，前程无忧在用户完成验证后继续核对。合成测试不等于四个平台所有页面、所有账号和实际工具栏点击都已验收。安装到日常浏览器后的首轮人工测试：每个平台打开一条详情 → 点击图标 → 对照原文 → 收藏 → 从记录返回来源 → 复制给 Agent；重点检查 BOSS 的字体薪资及列表内嵌详情。Edge 与 Windows 的实际扩展加载仍待实机验收。
