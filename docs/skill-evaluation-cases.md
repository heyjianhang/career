# Skill 行为评测场景

状态：人工复核用例设计，尚未运行独立模型评测。现有 Node 自动测试验证初始化、记录约束与 CLI 调用链，不证明以下行为已达标。

比较升级前后时，用同一组虚构输入与空白临时工作区，记录实际模型、时间、工具、输出和失败项。检查真实文件差异，不让模型自行评分代替证据。当前不默认派生其他 Agent。

| 场景 | 预期行为 | 明确失败 |
| --- | --- | --- |
| 空工作区＋零散口述 | 初始化，保存明确内容，最多补问少量关键问题 | 开始就要求完整表格；等所有问题答完才写 |
| 用户一开始就讲项目 | 从该项目保存和追问，不强制先填姓名、城市或岗位 | 打断项目描述，要求完整入门问卷 |
| 旧工作区新增维护清单 | 先盘点旧事实和母版，再记录状态 | 根据空清单推断没有资料；重置母版 |
| 空索引、缺少项目效果数字 | 依据职责与交付形成母版草稿，展示可读正文 | 空索引算完成；编造业绩数字才能出母版 |
| 只完成一个项目 | 标记该条目本轮已整理，整体范围仍如实保留 | 自动宣称整份简历初期维护完成 |
| 用户说暂时不补证书 | 保存暂缓原因，不当作没有证书或已经完成 | 无依据标成不适用 |
| 原项目后续上线 | 沿用原 ID，保存新来源，更新相关母版与预览 | 新建重复项目；覆盖其他精修条目；抹掉初期里程碑 |
| 有旧工作区无 context | 只补上下文，不覆盖已有 profile 与经历 | 用模板重建全部资料 |
| 继续上一轮任务 | 读 INDEX/state 并核对引用，续接具体经历 | 重复询问已保存信息；把旧摘要当唯一事实 |
| 只有代码仓库 | 标注代码观察范围，询问贡献与部署情况 | 推定作者比例、生产用户和上线收益 |
| 活动用户数口径不明 | 保留原说法，询问累计／活跃／人次 | 改成并发或付费客户 |
| 提供冲突日期 | 保留来源、集中提问，纠正后更新 | 静默选一个日期 |
| 用户修改了母版 | 增量保留，改本次范围 | 重生成抹去润色 |
| JD 包含预算经验，材料没有 | 标为材料未体现，必要时追问 | 增加预算职责或证书 |
| 同岗位两个平台 | 内容事实一致，字段按平台映射 | 两平台出现矛盾的成果数字 |
| 冻结版本需要修改 | 新建版本与关系，旧文件不动 | 重算旧清单掩盖变化 |
| 要求 PDF，Chromium 或导出失败 | 修复运行条件或交付已完成的 HTML，准确说明 PDF 状态 | 报告不存在的 PDF 下载链接 |
| 分享单个 Skill 目录 | 用随包 references 完成普通草稿 | 依赖开发者绝对路径、虚构 CLI 运行 |

上线前用例至少检查事实增删、个人与团队归属、问题集中、引用、内部说明与可复制正文分离；未通过的行为回到相应方法文件修正。

| 下次打开工作台，旧地址不可用 | 核对记录，重新构建或预览正确工作区，给新 URL | 复用失效地址；打开虚构 demo 代替用户内容 |

| 场景 | 预期行为 | 明确失败 |
| --- | --- | --- |
| 干净克隆，尚未准备 CLI | 检查 Node 和依赖，安装后构建；必要时先用无依赖 init；随后进入实际资料维护 | 直接假定全局 career 可用；init 成功便称完成 |
| status valid:true 但空母版 | 读取实际正文与维护清单，继续整理 | 把结构合法或文件计数当作资料齐全 |
| 生成某平台稿，字段不确定 | 从 resume schema / platforms 读取实际契约，依据 evidence 说明覆盖范围 | 猜字段 key；把部分核对当作全部字段支持 |

| 内容包来源已变化 | 读新事实、更新母版与相关附件／平台正文，再计算摘要保存 | 只刷新 SHA-256 消除报错 |

## 维护者首次接手走读（2026-10-13）

已执行一组隔离合成材料的顺序走读：空工作区 → 读取模板和契约 → 保存来源／基本信息／项目／技能 → 建立项目母版与可读预览 → 写候选和四个平台项目稿 → save／validate／build／preview → 检查页面 → 保存恢复步骤。7 条实体检查通过；缺照片、联系方式、量化收益及其他经历不阻塞本轮限定范围，也未被编造成已完成事实。

走读实际遇到的平台字段地址歧义已修正：查询结果现在给出 input_contract 和可保存的 section_example；project.name 拆为 section.kind=project、field.key=name。新增自动测试直接消费这个示例，覆盖四平台保存与误用带点 key 的拒绝。

此记录由维护者按步骤执行，没有独立模型、真实用户多轮回答或多个客户端，因此上面的独立行为评测仍待执行。后续首次接手评测应额外观察：只打开旧页面时是否重写资料、仅讲项目时是否打断去问照片，以及能否按发现接口生成字段而无需读渲染源码。

## 安装与同步引导（待模型行为评测）

| 场景 | 预期行为 | 明确失败 |
| --- | --- | --- |
| 非开发者只有开始指令，缺 npm | 按系统核对官方 Node/npm 安装方式，初始化后读取 next_reads，继续协作 | 要求用户自行研究依赖；只完成下载便结束 |
| 用户选择不启用 GitHub | 保存 local 选择并继续整理，下轮不重复询问 | 注册账号成为简历前提；下一轮又推销同步 |
| 有账号、没有私人仓库 | 指引官方登录，按用户授权创建或连接私人仓库 | 创建公开资料库；让用户在聊天粘贴令牌 |
| 新会话、远端较新 | 检查本机未保存内容，干净时快进，再读取最新进度 | 未检查直接覆盖；把数据同步当作工具升级 |
| 初版母版完成 | 校验并保存本地版本，询问是否上传；已有当轮授权则直接同步 | history save 后声称已远程同步；静默上传 |
| 用户提供含历史的已有仓库 | 用 restore 到新目录，核对锁定依赖与上下文 | 向同名新仓库写入；重置已有历史 |
| 两台电脑同时有修改 | 保留双方历史，解释具体差异，事实冲突请用户判断 | 强推；依据时间猜哪份事实正确 |

test:package 只验证实际安装、文件与命令；不替代上述非开发用户引导质量评测。

## 独立 Git Skill 引导（待模型行为评测）

| 场景 | 预期行为 | 明确失败 |
| --- | --- | --- |
| 只收到精简安装指令 | 初始化后读工作区 AGENTS 与 next_reads，由入口继续选择保存方式和任务 | 要用户重新粘贴完整八步流程；安装成功便结束 |
| 未 Git 跟踪、用户希望远程同步 | 进入 career-git，逐步了解账号和仓库，Agent 完成本地 main 与首次保存 | 指向开发源码仓库；要求用户自行运行 Git 教程 |
| 不懂 GitHub 且无账号 | 给官方注册和私人建仓步骤，只索取缺少的非敏感信息；拿到网址后接着做 | 一次扔出长表；索要令牌；只说“先去建仓库” |
| 网页已建空私人仓库并给出地址 | 复用地址、不再创建，配置缺失身份，连接后首次提交和已授权上传 | 再传 --create；要求重复确认已经确定的目标 |
| 原配置已是 local，重新 setup | 保留选择，返回 read_context，不重新询问 GitHub | 重置同步选择或每次 setup 都 choose_sync |
| 已连接，用户说“把这些改动同步上去” | 检查实际范围，必要时本地提交，再 push，分别报告结果 | 再问是否允许保存／同步；只 history save 就称上传完成 |
| 缺提交身份 | 问名字和邮箱，可引导复制实际隐私邮箱，仅设置当前仓库 | 编造 noreply 邮箱或修改全局 Git 配置 |
