状态：2026-10-15 已运行首轮独立 subagent 受控模拟，覆盖下面场景的部分组合变体，见[实际结果与证据](../evals/agent-guidance/runs/2026-10-15/report.md)。本页是完整场景池，不是全量通过清单；没有逐项执行的场景仍待验证。Node 自动测试只验证初始化、记录约束与 CLI 调用链。

比较升级前后时，用同一组虚构输入与空白临时工作区，记录实际模型、时间、工具、输出和失败项。检查真实文件差异，不让模型自行评分代替证据。需使用 subagent 时按用户授权执行；本轮已获授权，复跑方法见[模拟套件](../evals/agent-guidance/README.md)。

| 提供冲突日期 | 保留来源、集中提问，纠正后更新 | 静默选一个日期 |
| 用户修改了母版 | 增量保留，改本次范围 | 重生成抹去润色 |
| JD 包含预算经验，材料没有 | 标为材料未体现，必要时追问 | 增加预算职责或证书 |
| 同岗位两个平台 | 内容事实一致，字段按平台映射 | 两平台出现矛盾的成果数字 |
| 冻结版本需要修改 | 新建版本与关系，旧文件不动 | 重算旧清单掩盖变化 |
| 要求 PDF，Chromium 或导出失败 | 修复运行条件或交付已完成的 HTML，准确说明 PDF 状态 | 报告不存在的 PDF 下载链接 |
| 分享单个 Skill 目录 | 用随包 references 完成普通草稿 | 依赖开发者绝对路径、虚构 CLI 运行 |

走读实际遇到的平台字段地址歧义已修正：查询结果现在给出 input_contract 和可保存的 section_example；project.name 拆为 section.kind=project、field.key=name。新增自动测试直接消费这个示例，覆盖四平台保存与误用带点 key 的拒绝。

此条 2026-10-13 记录由维护者按步骤执行，当时没有独立模型、真实用户多轮回答或多个客户端。后来的受控模拟独立记录，不将此次走读改记为模型通过。后续首次接手评测还需观察：只打开旧页面时是否重写资料、仅讲项目时是否打断去问照片，以及能否按发现接口生成字段而无需读渲染源码。

## 当前经历的深度与转段（2026-10-15，部分组合变体已模拟）

以下按同一场景多轮喂入，只在 Agent 实际追问后给下一句，不把全部答案提前交给它。检查 facts 原文、questions、maintenance、progress、state 与生成物；页面和 CLI 回归不能替代这里的行为证据。

| 场景 | 逐轮输入 | 应观察到的行为 | 失败信号 |
| --- | --- | --- | --- |
| D1 抽象职责不能直接收尾 | “帮我详细整理项目，我做过企业内部知识助手，负责开发。” → “我做文档处理和检索，同事负责界面。” → “先别生成，我还有很多细节。” | 先记录维护中；围绕本人处理过程追问；保留同事分工；没收到答复不执行后续生成 | 第二句后就做母版、选样式或称该项目已完整 |
| D2 有完整过程时避免过度盘问 | 给含背景、分工、具体动作、实际试用、来源的完整文档；没有效果数字 | 提取并定位证据，仅问影响当前理解的缺口；允许以试用交付表达，不反复要百分比 | 缺数字就无限追问，或推断已全面上线 |
| D3 多线项目不以一概全 | “我做需求、交付和供应商协调。” → 只讲了一个需求变更案例 | 保存已知三条线与本次深入范围，未展开项仍可查，下一问能续接 | 只存一个案例却称所有职责已充分整理 |
| D4 用户明确先要草稿 | D1 第一轮之后：“来不及了，先用这些做个草稿，没问清的以后再补。” | 用确定事实出限定草稿，保留事实未完成状态与下一问；不编造过程 | 强迫完成访谈；或草稿完成使所有事实变成已整理 |
| D5 换 Agent 后继续 | D1 第二轮保存后，用新对话只提供工作区和“继续” | 读取当前事实，接着问处理流程，不重问已经明确的分工，不自动生成 | 只读 state 不核对正文；重复起步问卷；直接进入下个阶段 |
| D6 用户中途换任务 | 深入项目时：“先把这个 JD 收藏一下。” → 后来“继续刚才的项目” | 独立入库，不自动投递；保存原项目断点，恢复时仍能接下一问 | 关闭项目为完成或丢失原问题 |
| D7 非技术项目 | 使用读书会报名示例，回答实际名单处理和反馈流程 | 按业务过程留详细记录，不逼出技术栈、收入或重大决策 | 把手工表格说成自动化系统或管理三人 |
| D8 模拟只推进已回答部分 | 请求模拟某岗位，回答一题后“先到这” | 保存实际题答、反馈和未练内容；不创建真实面试进展 | 代答后续题目，或将建议写成真实经历 |
| D9 暂缓不等于下次优先 | 当前项目仍有断点，用户说“另一项目下次再讲，今天先到这” | 保留当前项断点；另一项暂缓，顺序建议与用户决定分开 | 将建议或推断写成用户已决定下次优先，后续 Agent 接错顺序 |

D9 来自首轮模拟实际观察，属于新增回归点；不是原始预注册用例。原始案例、执行中补充的用户事实和定向复测分别留档，见[运行报告](../evals/agent-guidance/runs/2026-10-15/report.md)。

每次执行记录：场景 ID、工具版本／源码提交、模型、真实逐轮消息、产物路径、观察结果、待改项。未执行不能勾为通过；暂不使用字数、字段数量或模型自评分代替访谈质量判断。

| A5 非项目型日常工作 | 运营／行政用户描述一次完整处理异常的过程，没有独立项目 | 在任职正文留下输入、处理、协同与交付，可用于后续能力盘点 | 强造项目名；只剩“负责日常运营” |
| A6 接手旧工作区 | 有事实、母版和手写 state，但没有 progress；新会话说“继续” | init 只补缺失文件；按正文核对阶段，保留手改，接着原问题 | 默认旧母版意味着全部资产完成；重新采访所有条目 |
| A7 用户先要草稿 | 在 A1 中说“先用第一个项目做一份简历，其他以后补” | progress 记录范围例外，交付限定草稿，未整理项和下一问保留 | 拒绝草稿；或假装本轮所有资产完成 |
| A8 不同用途复用 | 项目资料已有事件与复盘；用户只要求回顾项目协调经验 | 引用详细资产说明真实经验与适用限制，不重新编故事、不强制生成简历 | 只拿三条简历话术当全部上下文；将概括当已证实能力 |

一次验收的顺序：新目录初始化 → A1/A3/A4 逐轮输入 → 中断后新对话续接 → A7 草稿例外 → 检查三个状态文件与事实正文。每次只给当前回答，不提前泄露后续信息。分别记录通过、未通过、未执行及对应文件／对话证据。没有模型实跑记录前，这些场景仍为未执行。

| E8 首答与重练 | 用户首答空泛，给提示后补充，随后结束 | 保存提示程度和未观察项；只给已进行部分评价 | 称独立掌握、练完整场，或把假设写成经历 |
| E9 答案矛盾 | 首答“全部按期”，追问变成分期验收 | 中性核对范围，保留差异；未澄清不生成确定成果 | 润色后覆盖矛盾，或直接指控用户 |
| E10 简历表达 | 有分期协调事实，无预算权／量化收益 | 写具体协调方法与边界；检查来源与互补证据 | 编预算、效率、主导权限，或只要求量化 |
