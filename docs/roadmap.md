# 产品路线图

career 面向个人求职全过程。经历与简历、岗位看板和本地求职跟踪已随桌面预览版交付，后续围绕同一份职业资料扩展平台协作与求职复盘。各渠道的可用能力以 [README 版本表](../README.md#版本与能力)为准；本文区分已有实现与规划，不承诺发布时间。

## 当前：经历与简历（已实现）

- Agent 引导安装、材料优先的渐进收集、来源与事实维护、可读简历母版。
- 针对用途或 JD 选材、版本留存、展示内容包与平台填写稿。
- 14 款样式、照片与链接、分页预览、本地 HTML/PDF 导出。
- 独立个人目录、本地 Git 历史、可选私人 GitHub 同步与换机恢复。

当前 Agent 可根据用户提供的 JD 做选材与解释。桌面 0.3.0-alpha.1 已包含岗位文件库、协作任务、评估记录命令和看板；npm 0.2.0 仍提供经历与简历流程。安装包与跨系统验证状态见[项目状态](context.md)。

## 岗位收集与分析（桌面预览版已交付）

career-board Skill 与 board/opportunity/task 命令已包含在桌面预览版和当前源码中，范围与验收见[岗位工作区](opportunities.md)。公共 npm 0.2.0 不包含此模块。

用户提供 JD 或岗位链接到本地岗位记录的流程已实现。[浏览器岗位收藏](browser-extension.md)目前是独立的源码扩展，手动读取当前页面并复制给 Agent，未随桌面分发；平台搜索、账号连接和状态同步继续按实际能力扩展。

- 保存岗位内容、公司、地点、薪资口径、来源链接与采集时间；相似岗位可以关联，保留原始来源。
- 结合用户方向和真实经历分析要求、相关证据、信息缺口与需要核实的问题。
- 保存 Agent 的分析及其关联事实，支持并排比较、优先级与笔记；分析随新资料更新。
- 平台筛选不支持的条件明确返回，不用猜测补齐未知字段。

完成标准：用户能回看“为什么关注这个岗位”，分析能追溯到具体 JD 和经历，岗位与所用简历版本可以关联。

## 求职跟踪（本地已实现，平台同步规划中）

本地岗位卡片已具备阶段／结果与归档、五星、自由文档、面试轮次和简历关联。一份简历可以关联多个岗位；实际投递由用户确认后留存内容快照。简历卡片、双向编辑与历史记录的具体边界见[统一简历包](resume-packages.md)。以下平台协作仍按阶段扩展。

- 看板展示用户维护的阶段、优先级、下一步和结果；详情保留时间线、笔记与相关材料。
- 平台观察到的状态与用户维护的本地阶段分别保存，刷新平台信息不覆盖个人判断。
- 沟通辅助先覆盖首次打招呼草稿，后续重点是记录和跟进；发送在用户明确授权后执行并记录实际结果。
- 平台读取、同步及账号连接根据各平台能力逐步接入；遇到登录失效、验证或限流，返回清晰状态。

完成标准：任一申请都能查到当时的简历、最近进展及下一步。未知发送结果不当成失败重发，未读到回复也不等于确认没有回复。

## 面试辅助（需求已登记，待实现）

2026-10-17 已完成[需求与提示词设计](plans/interview-assist/design.md)及[可点击线框](plans/interview-assist/index.html)。用户要求先记录，当前暂缓实现，优先实现桌面软件更新入口。

- 从求职看板选择岗位、真实面试轮次及关联简历；复用现有资料归属。
- 电脑或手机查看同一场会话，使用同一套设置；电脑负责收音、服务调用与保存。
- 可配置语音转写和文本模型供应商，官方开通引导、热词、音频检测与资料范围。
- 提示词分为问题整理、基于 JD／真实履历事实的参考回答、基于真实转写的复盘；保留来源与事实缺口。
- 结束后记录归入对应轮次，实际回答与生成参考分开；不自动判断招聘结果。

当前仅有合成数据线框，尚未接入录音、模型、手机配对或生产界面；不能宣称真实端到端可用。

## 持续扩展：求职复盘（规划）

从同一批岗位、申请和事件生成概览与指标，按平台、岗位方向、简历版本和时间范围观察进展。

- 指标带时间范围、样本量、来源和缺失说明。
- 复盘连接到具体申请与沟通事实，帮助调整岗位筛选、简历表达和后续行动。
- 看板、详情、时间线和分析使用同一份个人记录，避免形成相互矛盾的资料副本。

完成标准：用户能看清进展和数据空缺；不根据少量样本宣称某种改写必然提高录用率。

## 贯穿各阶段的技术约定

Skills 负责方法，Agent 负责分析与写作，CLI 负责可验证的读写和动作。后续本地界面/API 复用业务服务；平台适配器承担登录协议、原生 ID、分页、过滤和错误映射。

个人资料与上下文继续采用便于审阅和 Git 留存的 Markdown；需要结构化的内容通过明确 Schema 保存。岗位、申请、评估、简历版本、沟通与事件应有稳定关联。新增格式先确定迁移和兼容规则，不把旧资料静默转成另一个结构。

平台动作通过能力发现暴露，尚未实现的动作不出现在可执行命令清单中。跨平台任务逐项报告成功、失败或跳过，并设置有限请求范围；仅刷新用户关注的记录，批量范围不推断为批量发送授权。

## 维护路线图

新增模块先明确输入、资料归属、CLI 契约、Skill 引导和完成标准，再实现与验证。上线后同时更新本页、README、项目状态和实际能力发现。在线个人履历、Word 导出及其他客户端集成作为后续扩展候选，不预置无实现的空模块。
