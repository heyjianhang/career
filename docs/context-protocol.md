# 渐进加载与持续更新的上下文

本协议用于用户 AGENTS、五个 Skills 和初始化工具。来源、事实与母版沿用 v2 Markdown；CLI 消费 Agent 写好的 career-presentation/v1 内容包生成成果页，不替换事实层。所有私人路径相对于用户独立资料目录。

## 两种渐进

读取按任务逐层展开：入口 → 小型状态索引 → 本次 Skill → 相关资料／方法参考。积累按证据更新：新材料 → 已知事实 → 待确认问题 → 用户决定／反馈 → 下一步。每轮只维护有变化的部分。

AGENTS 保存稳定导航，不存个人资料和聊天历史；Skill 保存可共享方法，不保存某个用户的进度。它们不是常驻进程，文件也不会自动加载，具体读写由宿主 Agent 执行。

## 项目上下文的所有权

- [context.md](context.md) 保存项目当前实现、验证状态、未实现内容、待解决问题和下一步。开发 Agent 先从这里续接，再检查实际代码。
- [decisions/](decisions/) 保存长期有效的架构决定、原因与影响。新决定改变旧决定时注明替代关系。
- architecture、data-model、presentation 与 development 保存当前架构、契约和开发约定；context 通过链接引用，不复制整份设计。
- 根 AGENTS 只保留全局约定、入口和任务路由。求职任务的方法、参考资料与模板保存在对应 Skill 内。

以上内容随公共仓库维护，只记录项目开发信息。个人求职目标、简历内容和具体投递进展仍属于 workspace/context，不写入 docs。项目开发完成后先保存实际改动与验证结果，再更新 context 的状态；尚未实现的设计始终注明提案。

## 私人上下文的所有权

下表路径均相对于个人 workspace。起步模板由仓库 `templates/context/` 提供；它们用于跨模块续接，不属于某一个求职任务的写作方法。

| 文件 | 维护内容 | 不承担的职责 |
| --- | --- | --- |
| context/INDEX.md | 简短入口、当前焦点、重要文件与最近交接的路径 | 不复制所有经历或堆积历史 |
| context/goals.md | 目标岗位、城市、工作方式、时间安排、薪酬口径、用户协作偏好及来源日期 | 不把意向写成已经具备的资历 |
| context/state.md | 本轮维护对象、实际产物、待回答问题 ID、下一步；引用 maintenance | 不复制模块与逐条进度表，不宣称未执行内容已完成 |
| context/decisions.md | 已采纳决定、依据、范围、替代关系 | 不把 Agent 建议记成用户决定 |
| context/feedback.md | 具体反馈、触发场景、适用范围、是否已修正 | 不因一次拒信推断录用因果 |
| context/sessions/*.md | 长任务需要时保存的交接记录 | 不默认逐轮生成聊天副本 |
| resume/questions.md | 与履历事实有关的缺口及解决状态 | 不再在 state 复制完整问题 |
| resume/maintenance.md | 模块及具体经历状态、母版待更新事项、初期完成日期与范围 | 不成为第二个事实库，不由空目录推断不适用 |

context 内当前是普通 Markdown，不增加另一套履历 schema。文件中指向事实 ID 和相对工作区路径，引用优于重复抄写。

## 冷启动与续接

无 career.json：按 career-setup 准备独立工作区、读取 next_reads 并处理同步选择，随后进入 career-intake。材料已给出就直接提取；内容为空时主动引导维护一个具体主题，边聊边保存，不要求先填写求职目标或完整问卷。

有配置、无 context 或 maintenance：重新初始化只补缺失文件。随后根据真实产物盘点模块与条目，不能因为目录存在就把履历标为整理完成，也不能因清单刚建立就把旧资料当作空白。

用户说“继续”：先读 INDEX/state 和 maintenance 中当前对象，检查其指向的文件，补读本次必要信息。用户说“最近做了一个项目”时进入具体项目维护与母版更新。摘要与文件矛盾时以证据和用户最新说明为准，纠正摘要并说明。

## 信息状态

记录目标、决定或反馈时标明日期和依据。区分用户明确说明、材料观察、待确认推断。用户表示“考虑北京”不能转写成“只接受北京”；薪酬需保留月薪／年包、税前／税后、薪数等原始口径，未知则保留。

一段经历的来源变更仍在 sources/facts 维护。context 中只链接结果，不成为第二个事实库。用户纠正旧决定时保留替代关系，历史状态不作为当前约束继续执行。

## 收尾与精进

有实质写入或明确决定时，按顺序：保存实际产物 → 更新 questions／goals／decisions 中受影响项 → 更新 maintenance 的具体状态及母版同步 → 更新 state 下一步与产物链接 → 必要时补交接记录。初期完成里程碑与当前更新状态分别维护；尚待回答不能写成用户同意。

反馈记录采用“观察 → 原因假设 → 本次调整 → 后续核对”。先判断是事实问题、表达问题、岗位选择问题还是输出格式问题，调整其所属层。一次面试结果不自动验证某种写法更好。

公共方法改进应附具体反例和复核场景；个人偏好留在私人上下文。未来模型评测可用合成材料比较升级前后输出，但未实际运行不得声称效果提升。

保持 INDEX 与 state 短小；累积历史移到按需读取的交接记录并保留索引。不要为控制篇幅丢失未解决问题或仍生效的决定。
