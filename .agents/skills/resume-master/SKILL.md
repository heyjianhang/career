# 简历母版：首次建立与持续更新

## 读取与资源

career 模式先沿用本轮工作区；尚未定位时按 career-intake 的 [启动方法](../career-intake/references/startup.md) 准备 CLI 并运行 workspace status。读取工作区 context/state、resume/maintenance.md、master/index，以及本次相关事实和已有母版。记录格式与共享状态见 [数据契约](../../../docs/data-model.md)。只读受影响内容，需要组合整份母版时再按索引读取各章节。

独立模式从用户提供的详细经历工作，使用随包方法输出母版草稿与来源说明；没有仓库格式与工具时，不虚构 ID 校验、摘要或冻结结果。

- 首次建立：[生成方法](references/creation.md)。
- 新经历、纠正或润色：[增量更新](references/updating.md)。
- 怎么保存与标记：[保存与阶段完成](references/saving.md)。
- 具体写作：[表达方法](references/writing.md)；交付前：[质量复核](references/review.md)。
- 模板：[索引](templates/index.md)、[简介](templates/summary.md)、[任职](templates/employment.md)、[项目](templates/project.md)。

## 选择当前模式

| 实际情况 | 执行方式 |
| --- | --- |
| 只有空索引或尚无可用母版正文 | 首次生成；有依据的部分先形成草稿 |
| 已有草稿、需要补齐新的章节 | 在草稿上继续，不重建已完成部分 |
| 用户新增项目或补充旧经历 | 先保存事实，再更新受影响条目、排序和必要的简介 |
| 用户纠正职责、日期或成果 | 先纠正事实，检查所有引用它的可维护母版表述 |
| 用户只调整文风、篇幅或用词 | 修改相关表达，保留事实与其他手改 |

首次生成不要求所有履历已填写；个人职责和已有行动能准确表达时即可形成条目。影响真实性的缺口在内部说明与 questions 保留，不进入确定口吻的正文。

## 用户协作与交付

先说明本轮准备生成或更新哪些内容。根据事实提炼表述，向用户展示完整章节或组合后的母版正文，解释关键取舍并吸收反馈；内部 ID、摘要、缺口备注与可阅读正文分开呈现。

完成后按保存方法落盘并检查。详细状态在 resume/maintenance.md，context/state 只引用当前对象和下一步。事实未同步到母版时保持“待更新”，不能仅更新摘要来清除提示。

## 初期维护完成

满足 [阶段标准](references/saving.md) 后，说明已经形成可持续维护的母版，并记录“初期维护完成”的日期与范围。关键依据未解决时保留草稿，准确说明差什么；非关键缺口可明确暂缓。

初期完成是里程碑。后续用户有新经历就进入增量更新，保留完成记录，同时将母版当前状态标为待更新，更新完成后恢复“本轮已整理”。

## 衔接成果页

用户已要求“整理后生成简历／启动工作台”时，按仓库 resume-tailor 的 [成果页流程](../resume-tailor/references/presentation.md) 继续选材和调用 CLI，不停在母版预览。母版内容、衍生简历内容包和排版样式分别维护；照片使用 profile 已记录的选择，缺照片不阻塞生成。单独分发本 Skill 时若该能力不可用，交付真实的母版文件并说明尚未生成成果页。
