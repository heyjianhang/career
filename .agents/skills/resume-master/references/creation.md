# 首次生成简历母版

## 开始条件

用户已有按类型标准整理的履历事实，或明确要求先用已有信息出草稿时开始。先检查 progress 本轮范围及资产核对阶段，再检查 maintenance、事实具体过程和仍待回答项；仅能准确写一条抽象职责不代表访谈完成。索引文件存在但 sections 为空仍属于首次建立；不把初始化生成的空文件当作母版已完成。

先说明：“本轮选定的经历已经整理并核对，我们接下来从这些详细资料提炼母版；原始过程会保留。”正在完整维护简历时主动衔接；用户限定本轮只记录事实时尊重该范围。

## 生成步骤

1. 按维护清单确认本轮范围，读取相关事实与来源，以及 INDEX 指向的当前岗位研究和证据映射。先列出实际存在的模块；没有任职但有学习与实践的用户，可以用教育、研究或项目组织母版，不制造工作经历。
2. 提炼任职和项目条目。先明确本人职责，再选择互补的行动与交付；结果尚未量化时保留准确的定性表达。条目既保留成熟要点，也保留后续可选用的不同侧面，不要求每条都压缩到相同长度。
3. 区分任职与项目的表达层次：任职讲职责范围与总体工作，项目讲具体问题、行动和交付。同一成果可以关联，但不复制成两项独立成果或重复计算。
4. 内容形成后再写个人简介，从已有事实概括共同能力、经历特点与实际贡献，不提前设定“专家”“负责人”等身份。主要事实不足以概括时可暂缓简介。
5. 组织母版索引。profile、教育、技能、语言和证书使用事实引用；summary、employment、project 使用母版条目。顺序按可读性和实际经历确定，避免虚构连续年限。
6. 展示各章节或整份初稿，请用户纠正误解与不符合本人表达的部分。普通风格偏好可以边看边改；未回答不等于认可，事实依据仍来自原材料与明确陈述。
7. 按 [保存方法](saving.md) 落盘、复核、生成可读预览并登记状态。尚未达到阶段标准时明确保持草稿和下一步。

用 [表达方法](writing.md) 改善具体句子，用 [质量复核](review.md) 检查真实性与贡献归属；不以不存在的量化结果换取简历“亮点”。
