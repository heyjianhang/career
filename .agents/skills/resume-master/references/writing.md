# 从经历素材到成熟表达

先判断读者能否看懂“对象是什么、你做了什么、结果是什么”。动作必须准确体现贡献程度；参与、协作本身可以是准确表达，不一律替换为主导。

写作前按 [资产方法](../../../../docs/career-assets.md) 核对上下文，表达只取有依据的部分。完整过程、决策与复盘留在 facts；为某一用途删去的细节不能从资产层同步删除。

## 先决定表达要证明什么

从事实中识别可被追问的贡献：执行交付、分析判断、跨团队协调、专业设计、持续改进等。每个主张必须能找到具体行动与结果，不按头衔自动推定。母版保留不同能力侧面的表达；面向某岗位的排序与删选留给 tailor。

写前做一份简短的内部对应：**拟表达的贡献 → 事实 ID 与章节 → 可用行动／交付 → 不可声称的范围**。一条要点突出一个主贡献，方法和结果服务于它；同一团队结果不能拆成多条各算一次本人功劳。两条内容若只是换词重复，合并后腾出位置呈现另一项证据。

## 从动作写到价值，不跳过中间环节

问自己：这个动作改变了哪个对象／流程？谁因此能够做什么？有什么实际依据？能回答到哪一层就写到哪一层，不能从“增加检索功能”直接跳到“企业降本增效”。

区分交付物（上线一个模块）、使用结果（被某团队用于流程）、业务结果（有口径的成本／收入变化）。只有前一层证据就停在那里。数字有条件才写：基线、时间窗、统计对象、样本和个人贡献要能解释；比例不明不倒推，估计不能伪装成精确统计。

动词按实际权限选择：执行／整理／实现说明直接工作；协调／推动需要具体干预和协作证据；设计需要方案决策依据；主导需要在重要决策与推进中确有相应责任。参与不是弱词，虚构主导才会损害可信度。

## 可选表达路径

- 有结果及口径：本人行动 + 对象／方法 + 有依据的结果。
- 结果尚不能量化：具体问题 + 本人完成的交付 + 已知使用或流程变化。
- 团队成果：本人负责的部分 + 团队最终结果，明确两者关系。
- 探索或未上线项目：目的 + 已实现范围 + 实际验证方式，不加生产规模。

篇幅取决于内容与阅读用途；母版先保留充分要点，目标版本才裁剪。不能为了压到一行加入难懂缩写，也不因缺少数字而删除有价值的工作。

## 虚构对照

素材：书店四场活动；本人负责报名表、到场核对、反馈汇总；三人团队；累计 60 人次到场。

可用：负责社区读书会的报名信息整理、到场核对与反馈汇总，参与三人团队完成四场活动，累计 60 人次到场。

不可用：独立策划四场活动，实现用户增长 60%，显著提升收入。这里独立策划、增长比例和收入效果都没有素材依据。

另一种无数字素材：将纸质审批材料整理为可检索电子归档，并编写交接说明。可以直接突出归档和交接，不需补成“效率提升 80%”。

### 项目管理：把“协调”写具体

事实：上线前客户增加导出需求；本人整理依赖与两种排期，向负责人说明影响；负责人批准分期，本人更新验收清单、跟踪联调。没有预算管理职责，也没有效率统计。

初稿：“负责项目管理，协调团队高质量交付。”读者看不到实际方法。

可用：“梳理新增导出需求的依赖与排期影响，提出整体延期和分期上线两种方案供负责人决策；按确认范围更新验收清单并跟踪联调。”

这里写出了协调的实质，但没有将负责人批准变成本人拍板。若最终验收尚未核实，不加“如期完成全部上线”。

### AI 应用：避免把应用写成算法研究

事实：本人实现文档处理、检索与引用展示，同事做界面；试点验收，尚无生产使用量或准确率基线。

可用：“实现知识助手的文档处理、检索和来源引用链路，与界面同事联调并参与试点验收。”若事实中已有权限或异常处理细节，可另提炼为质量保障要点；不能凭常见架构补入。

不可用：“自主研发大模型算法，实现企业级高并发平台，准确率提升 40%。”技术层级、规模、独立归属和数字都超过证据。

## 简介不是形容词集合

用目标方向（如已明确）、真实经验范围和两三类有来源的贡献概括。泛化词如“资深”“专家”“全栈”需要事实支撑；不能为了好听默认加入。没有年限汇总就不写数字年限。不要把期望从事的工作写成已有专业资历。

## 避免模板腔

保留具体名词与动作，删去无法核对的“赋能、全面、卓越、极大提升”等修饰。技术内容说明解决了什么问题；非技术内容不补技术栈。目标是读者能追问、用户能解释，而不是一味使用强动词。

项目事实中的可展示 links 保留在该项目母版的“项目链接”，用名称和完整网址对应记录。个人网页仍引用 profile。链接缺失时省略，不生成空占位；链接只证明可访问材料的位置，不能代替对职责和成果的核对。
