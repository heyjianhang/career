# 母版质量检查

逐条给出通过／需修改／缺依据及具体原因，不计算未经验证的综合分数。

1. 事实：日期、角色、数字、对象与来源一致吗？是否增加了不存在的认证或能力？
2. 归属：哪部分是个人、团队、项目背景？动词是否超过实际职责？
3. 具体：能看出实际行动、交付或变化吗？空泛形容词是否可删除？
4. 可追溯：重要表述能定位事实 ID 和对应章节吗？摘要是否在实质核对后生成？
5. 可解释：用户是否有材料支撑并能解释关键表述？代码观察或练习成果有没有误写成生产经验？
6. 可复用：母版是否保留了互补要点？是否为了一个 JD 过早删掉其他经历？
7. 增量维护：有没有覆盖用户润色或误改客观字段？

硬错误先修正；信息缺口保留为问题；只属于风格取舍的事项按已有偏好处理，不阻断普通编辑。格式校验与内容复核分别报告。

## 按影响区分问题，不给一堆同等重要的建议

| 级别 | 识别方法 | 处理 |
| --- | --- | --- |
| 事实／归属错误 | 新增数字、把协调写主导、试点写生产、团队收益全部算个人、时间冲突 | 修正具体句子或降为有依据表达；不能仅润色掩盖 |
| 重要能力没有表达出来 | 事实有关键行动，正文只有工具名／抽象职责，或选材与目标任务错位 | 回源提取行动和方法，解释补这一句能证明什么 |
| 读者难理解 | 名词无对象、因果跳跃、一句混了多项贡献、重复内容 | 补必要语境或拆分合并，不改变事实 |
| 风格选择 | 长短、动词、段落顺序在准确范围内有多种写法 | 依据用户偏好处理，不再启动整轮访谈 |

反馈使用“原句 → 问题及证据位置 → 修订句 → 剩余待核实点”。优先处理最影响真实性与理解的少数项，不仅给“突出亮点、量化成果”。若没有统计，可用真实交付和使用场景改善；不以缺数字判不合格。

最后反向检查：正文中的重要主张都能回到事实吗？选定的核心贡献有至少一条具体支撑吗？同一项成果是否重复计数？改变表达没有改掉其适用范围吗？母版详细并不等于成品必须全部展示。
