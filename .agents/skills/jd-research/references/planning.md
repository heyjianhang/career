# 求职方向与能力补足

## 方向判断

结合用户偏好、经历证据、可用准备时间与岗位要求提出选择，不用热门工具替用户决定职业方向。以实际任务命名方向；职位名称有歧义时给出可投关键词和应避开的职责特征。

每个方向说明：典型工作、现有优势、关键未知／差距、硬条件、取舍和下一步。可以分为“现在投并准备”“补一个关键环节再尝试”“较长期备选”，但分组由证据决定，不机械地给每人三个方向。不保证录用，也不把本科／硕士等硬条件当作短期补课项目。

材料不足时先给条件性建议，并问最能改变方向的一两个问题。例如没有团队管理经历证据，先核对实际职责，再推荐管理岗。用户暂时未提供简历时，可做需求地图与自查问题，不生成个性化能力诊断。

## 缺口类型决定行动

| 状态 | 应做什么 | 可验收的产物 |
| --- | --- | --- |
| 做过且有证据，简历没有体现 | 定位经历，改表达和选材 | 可追溯的新要点与项目顺序 |
| 用户说做过，原理／分工／结果还讲不清 | 回看材料，复盘一次实际决策与故障／难点 | 解释本人贡献的案例，能回应后续追问 |
| 部分相关经验 | 找到可迁移部分，补齐具体环节 | 包含边界和对照验证的练习／案例 |
| 材料未知 | 问具体行为或查资料 | 已确认事实或明确缺口 |
| 确认缺少目标岗位必要能力 | 有边界的学习与实践 | 可演示、可解释、可验证的成果 |
| 学历、资格、地区等限制 | 调整岗位范围或制定长期选项 | 符合条件的投递清单／长期路径 |

“项目用了某框架”不代表用户能解释运行机制；“没有写框架名”也不代表没做过相关任务。先判断真实行为和理解，再决定补写还是学习。

## 如何排优先级

优先处理影响目标岗位核心任务、在该岗位族多次出现、用户差距明确且准备成本合理的项目。单个强目标岗位的明确要求可以比大样本中的高频优先项更重要。不要按关键词频次直接排课程。

每项计划写明：

- **依据**：哪些岗位／任务要求它，为什么会影响投递或面试。
- **当前状态**：已有证据、未知或缺口；避免把所有事项都写为零基础。
- **动作**：读现有项目、复盘、专项练习、实践或选课中的具体一步。
- **完成标准**：能做出什么、解释什么、如何核对，不能只写“看完课程”。
- **安排**：结合用户可用时间给先后与建议周期；未知时标为建议，不伪造确定完成时间。

无需全部学完才开始投递。对当前匹配度较好的岗位同步投递／面试准备，后续用真实反馈修订计划；反馈少时不能把没有回复归因为某个技能不足。用户只要方向建议时不创建课程表；只有要求课程资源时再查证当前资料与版本。

## 虚构示例：同样的缺口，不同的处理

某客户运营岗位反复要求客户分层、续费分析和跨部门推动。用户已有投诉分类与跨部门跟进记录，但未做过续费分析：可以先强化实际协作案例，询问是否接触过客户分层，再安排一个以合成数据完成续费分析的练习。练习可用于展示学习成果，不能改写为原公司的营收提升。
