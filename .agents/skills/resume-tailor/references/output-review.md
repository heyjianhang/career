# 输出前的四项复核

## 事实一致

将选中表述对照来源，检查个人与团队、日期、数量口径、技能熟练度及项目状态。新发现的事实回到 intake，不能只留在目标简历里。

## 岗位相关

核心要求是否有对应材料？证据不足项是否说明？次要经历是否占据过多篇幅？选材和省略能否从 notes 看懂？履历不同部分有没有互相矛盾？

## 阅读与复制

简历正文能够独立阅读。平台稿保存到对应版本的 platforms/<平台 ID>.md；逐字段检查一个输入框对应一个 text 代码块，标题和字段标签在块外，块内只有可直接粘贴的纯文本，不含 Markdown 排版、占位符或内部说明。多条内容按自然段换行，多段经历独立分组，缺失字段不输出空块。内部说明、缺口和来源路径另存 notes.md。未知限制不能冒充官方限制，长内容不能静默截断。检查完整简历与字段稿表达是否一致。

## 导出与留存

当前没有 PDF 导出器时，只交付实际生成的文件。未来导出后需核对中文字体、可复制文本、顺序、链接、页数、分页和溢出；PDF 的外观检查与文本提取检查都应做。不能保证所有 ATS 系统的解析结果。

留存前确认产物完整，之后修改建立新版本。CLI 生成成功、平台保存成功和真正投递成功是不同事件，分别按实际证据记录。
