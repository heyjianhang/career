# 项目资产：先理解全貌，再深入关键过程

你的交付是一份下一位 Agent 能接着理解和使用的项目档案，简历短句是后续产物。先读 [资产记录与写作](../../../docs/career-assets.md) 与 [推进规则](../../../docs/agent-workflow.md)。详细记录不等于堆字数；不要为了填满模板编造情节、指标或技术实现。

## 接手

沿当前工作区使用 [intake 启动方法](../career-intake/references/startup.md) 的 CLI 入口；桌面入口按工作区 AGENTS 替换。读取 `context/progress.md` 的本轮范围、`context/state.md` 的当前问题、维护清单中当前项目，以及来源和已有正文。用户指定项目时从它开始，不重新做整个入门流程。

用名称、单位、时期和稳定 ID 判断新项目还是旧项目补充。只为新项目建立新 ID；改名、上线和纠正继续原 ID。先读已有材料，初始文件也允许只有已知事实：不要等问完才保存，更不要把初始文件视为完成档案。

## 引导与落盘

1. 说明会先把项目来龙去脉记详细，后续再提炼简历。结合已知内容起问，不重复索取答案。
2. 先建立项目地图：背景、服务对象、目标、范围、阶段、参与角色和已知工作线。未知部分留在清单里，不能因为用户先讲了一个细节就把它当成项目全部。
3. 按 [深挖方法](references/deep-interview.md)，围绕一个关键点一轮一问，随回答追踪本人动作、决策边界、实际取舍与结果。先听和保存，再决定下一问。
4. 使用兼容的 [项目模板](../career-intake/templates/facts/project.md)，保存 `resume/facts/projects/<project-id>.md`。核心章节下可增加工作线与事件三级标题；任职项目用 employment_id 关联。来源、问题和进度按 [保存方法](../career-intake/references/saving.md) 维护。
5. 回读正文并展示有代表性的整理；遗漏细节补回、误解纠正。有上下文价值的失败、返工和未采纳方案留在资产层。工具校验不代替理解深度。

## 何时算这一项本轮整理完

- 本轮范围已明确，项目全貌、本人参与时期与角色边界可解释。
- 本轮纳入的主要工作线已经展开；代表性关键事件有具体过程、真实选择和交付依据。其余线索逐一注明尚未展开、暂缓或不在本轮。
- 结果区分演示、试用、上线、维护与停止；未取得的量化信息如实保留。
- 事实、个人复盘与 Agent 待核对理解分开；重要归属矛盾已解决或排除，正文已保存并展示。

不能因一个事件写得够长就完成整个复杂项目，也不能因无数字而无限追问。标记本条“本轮已整理”时写出范围与依据；大阶段是否可推进由 progress 中全部纳入范围决定。只要求沉淀资产时在这里交接；已要求简历时，等本轮资产核对通过再进入 resume-master。明确快速草稿例外照用户要求执行，资产继续保留未完成状态。

独立使用时可以按同样方法在用户指定位置写项目档案、来源与下一问；缺少 career 工作区或工具时，不声称已登记到库或校验通过。
