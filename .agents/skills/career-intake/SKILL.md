# 交互式履历维护

## 从当前状态开始

在 career 工作区先遵循 [引导与推进规则](../../../docs/agent-workflow.md)。本 Skill 的核心交付是可继续追问、可复用的详细事实；能提炼成简历短句不等于当前经历已整理充分。独立使用时按本 Skill 的逐项循环和类型标准执行。

在个人工作区，按 [启动与空白引导](references/startup.md) 用 `workspace status --json` 检查工作区，缺文件时 `workspace init` 补齐；完整命令入口与准备方式见启动方法。再读 context/progress.md、本轮 state 与 resume/maintenance.md。大阶段和范围在 progress，当前一项和下一问在 state；不要仅凭单条经历的状态推进整个任务。旧工作区先盘点，用户已指定经历就从该经历开始。只读取当前需要的事实、来源与问题。

首次写本工作区记录前，读仓库的 [数据契约](../../../docs/data-model.md) 和本次类型模板。来源、事实、问题、维护清单与 state 由 Agent 用文件编辑工具写入；CLI 负责初始化和校验，没有“自动收集／保存事实”的命令。每轮交付已保存的内容与一个可继续的问题，不把模板交给用户填写。

首次使用时先主动说明：“我会先和你把每段经历的背景、分工和关键过程详细聊清，边聊边留下可复用的职业资料；需要简历时，再从中提炼。”已有材料先提取；确实为空时，选择一项并解释如何开始，不只回复“请提供材料”。

进入基本信息维护时，按 [照片收集](references/profile.md#简历照片可选) 主动提醒一次可选照片，记录选择和素材；用户正在讲项目时不插入照片提问。已暂缓或选择不展示时继续整理，不重复催要。

独立分享整个 Skill 时，使用随包方法和模板，在用户指定位置或回复中输出履历草稿、问题清单和维护进度；没有仓库工具时不声称已完成 career 数据校验。导入 career 再映射稳定 ID 和共享格式。

## 每项维护的循环

1. **说明本轮主题。** 根据维护清单、现有材料和用户意图选一项，说明已有内容与本轮要补充什么。空白时提出具体起点；学生可从教育或课程项目开始，已有任职者可从最近一段工作开始。
2. **先提取再追问。** 读取材料，保存已明确部分；结合该类型的方法发现关键缺口，每轮少量问题，避免重复索取答案或把全部模板交给用户填。
3. **随回答保存。** 按落盘步骤登记来源、匹配稳定 ID、更新事实及 questions。暂时答不出的内容保留未知；先处理能推进的部分。
4. **给用户看整理结果。** 用可纠正的表述展示本人范围、行动和成果。事实冲突需要核对；普通表达可根据已有偏好直接改善，不要求逐字段确认。
5. **核对深度再继续。** 对照类型标准回读正文：是否仍只有抽象职责、是否缺本人具体过程。仍需追问时保持“维护中”，记录下一个具体问题；已满足本轮范围才标记“本轮已整理”，说明判断依据和非阻塞缺口。用户跳过时记录暂缓原因，不能冒充整理完成。模块状态按已知条目汇总。
6. **核对大阶段再衔接。** 一项完成后先回到 progress 的本轮范围：还有纳入的经历未展开就继续访谈，不自动写母版。范围内资产核对通过后，再由 resume-master 建立或更新相关表达。用户明确先要草稿、只选某批资料或已约定分批交付时按该范围执行，保留其他项与例外原因，不伪装整轮资产已完成。只记录资产时保存母版待更新事项，不扩大任务。

## 更新已有经历

“最近做了一个项目”“那个项目上线了”“这段经历我当时只是参与”都进入维护循环。先区分新增经历、原经历的新进展和事实纠正；新经历建新 ID，既有经历沿用 ID。保存新来源、更新受影响的问题与事实，维护清单标记相关母版待更新，其他内容保留。

每轮更新 context/state 的本轮终点、当前对象／阶段、已保存产物、待回答问题 ID、下一问与转段条件。履历详情只在 facts，模块／条目状态只在 maintenance，大阶段与范围变更只在 progress；具体保存规则见 [落盘步骤](references/saving.md)。

用户已要求整套生成时，把“资料 → 母版 → 内容包 → 本地成果页”作为同一个任务续接，按上述转段条件使用 resume-master、resume-tailor；不在每次切换 Skill 时重新询问是否继续，也不因为想尽快交付页面而跳过当前访谈。缺少仓库工具的独立模式只交付实际完成的草稿和素材引用。
