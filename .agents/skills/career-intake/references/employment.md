# 工作经历的维护

## 开始与判断

先识别已有任职，按用户指定或最近一段进入。空白时引导：“我们先把这段工作讲清楚：你在哪个单位、担任什么角色，平时主要负责什么？”职位和单位已知时直接从具体职责开始。

## 访谈与专业判断

- 区分公司、部门、职位、实习／兼职／正式任职和本人参与时间。派驻或外包场景分别记录雇佣关系与服务对象，不把客户直接写成雇主。
- 先了解职责范围，再选一个具体事件追问障碍、行动、交付和变化。管理团队规模、跨部门协调与本人决策权分别核对。
- 职责变化或晋升保留阶段信息；明显不同职位阶段需要独立记录时保留单位关联，避免重叠年限累加。
- 结果区分个人贡献与团队表现。有数值时保存时间、单位与统计范围；没有数字也可通过实际交付、流程变化与使用反馈描述。

## 保存

用 [employment 模板](../templates/facts/employment.md)，保存到 `resume/facts/employment/<id>.md`，稳定 ID 使用 `employment-*`。职责、业绩和补充范围分别写入正文。具体项目可另建项目事实并用 employment_id 关联，按 [落盘步骤](saving.md) 保存来源、问题与进度。

## 本轮已整理与后续更新

单位与任职关系、时间／状态、本人职责明确，已知主要行动或交付能准确说明，并展示给用户，即可标记本轮已整理。工作刚开始、尚无结果可以如实记录，不强求成果数字；存在职责归属冲突则继续维护或明确排除争议表述。

离职、晋升、新成果或职责纠正更新对应阶段；新的任职关系建立新记录。先改事实，再标记关联母版任职／项目及简介中的相关表述待更新，不重写其他公司经历。
