# 从对话整理资料到生成母版

## 第一次使用

按 [启动方法](startup.md) 准备工作区。对话从根 AGENTS 进入 career-intake。有材料先读材料，正在讲项目就从该项目开始，不要求用户先填写全部基本信息、求职方向或城市。工作区为空时主动提出容易回答的起点。

一份材料可拆为多个事实；一次新消息也可能只补充原记录。判断重复时结合单位、名称、时间与上下文，稳定 ID 延续原记录。需要澄清时先保存确定部分，再问当前最关键的问题。

## 从事实到母版

事实保存完整内容和证据，母版维护清楚、成熟的表达。母版不受特定平台字数限制。来源变化后按任务范围检查，保留手改内容，不能自动覆写全部母版或历史版本。

## 展示与续接

逐项引导的节奏见 [虚构对话](example-conversation.md)。维护状态在 maintenance.md，问题集中在 questions.md，context/state 只记录当前对象、实际产物和下一步。有来源、能准确表达的经历先生成母版条目，再按索引组合 master-preview.md，给用户看实际正文。

说“继续”时读取现有进度并核对相关文件，不重复询问已保存的答案。仅要求资料维护时完成母版范围即可；用户已要求生成简历、PDF 或工作台时，母版可用后直接衔接 resume-tailor 的内容包与 CLI 流程，不重新索要资料或要求提供 JD。已有 JD 的定制与平台版本仍由 resume-tailor 承担。

## 更新规则

| 变化 | 更新位置 |
| --- | --- |
| 新事实／事实纠正 | sources、facts、questions，检查母版关联 |
| 成熟表述改进 | 指定 master 条目，不改事实 |
| 新项目或原项目进展 | 检查记录身份，保存事实，再更新相关母版及预览 |
| 中断后续接 | state、maintenance 指向的具体条目；不重做完整访谈 |

完成后给出文件位置、已明确内容和关键缺口。初期维护是否完成按母版 Skill 的实际产物标准判断；结构检查通过不等于履历已经整理充分。

## 既有私人资料

旧 career-vault 可以作为来源，但初始化不扫描、不移动、不覆盖旧仓库。明确执行迁移时：先保留原件及未提交修改，映射到新路径，保留稳定 ID、专业细节和缺口，修复引用后再检查。旧岗位草稿不自动升级为通用母版。
