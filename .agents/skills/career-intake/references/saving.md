# 每轮访谈如何保存

以下路径相对于用户工作区。格式与字段类型遵循仓库共享契约；模板在本 Skill 内，填写结果保存到工作区。

这些 Markdown 文件由 Agent 的文件编辑工具创建／更新，目录不存在时按需创建。`workspace init` 只准备骨架，`workspace check` 只检查，`resume save` 只接收展示 JSON；三者都不会替你保存访谈正文。首次写入前读取 [数据契约](../../../../docs/data-model.md)，不从空白模板猜枚举和引用规则。

1. **读取已有记录。** 用当前文件、稳定 ID 和单位／时间／名称判断是否为同一条经历；先读原文，保留未知字段与手改。日期精度不足用原有年份或月份，不自行补日期。
2. **登记来源。** 新材料在 `resume/sources/<source-id>/source.md` 记录类型、实际取得时间、原材料位置、已明确陈述和提取限制。使用 [来源模板](../templates/source.md)。口述记为 user-statement；同一次访谈可继续补充其来源记录，保留更正前后的依据。原件保留，不把不相干文件默认全部复制。
3. **更新事实。** 新记录从相应类型模板建立，替换占位 ID 和日期；已有记录沿用 ID。`source_ids` 关联真实来源。事实 YAML 保存固定字段，正文保存背景、职责、行动、成果与来源定位。完整性未知用 null，实际未发生与未提供分开记录。
4. **集中处理问题。** 影响真实性或完整性的缺口写入 `resume/questions.md`，使用稳定 question ID，关联事实 ID、已有依据和要补什么。回答后先改来源／事实，再将问题标记已解决；用户暂不补充时保留问题与暂缓原因。[问题模板](../templates/questions.md)。
5. **核对写入。** 回读本次文件，检查来源、贡献归属和日期；执行 `npm run career -- workspace check --workspace "<工作区>" --json`（环境准备见 [启动方法](startup.md)）。错误修复后再报告；警告和未完成项如实保留。校验失败或工具不可用不能记为校验通过。
6. **更新详细状态。** 在 `resume/maintenance.md` 更新模块及本条经历、事实路径、问题 ID、母版关系和下次动作。先有实际文件再标记进展；初始化模板见 [维护清单](../templates/maintenance.md)，状态规则见 [维护状态](maintenance.md)。
7. **登记母版影响。** 已有母版引用该事实时标为待更新；新经历标明尚未加入母版。无法充分判断影响时先记录待核对，不靠替换 based_on 摘要消除变化提示。
8. **保存本轮交接。** context/state 记录当前对象、实际产物、待回答问题与下一步，链接详细维护项；不抄另一份履历或完整状态表。

每轮落盘一次或按材料批次保存即可，不要求每句话都建立一个文件。出现并发修改时先读取新内容并合并当前变更，不能用旧草稿覆盖。

用户可见反馈示例：“这段项目的背景、你的职责和交付已经保存，本轮可以先标记已整理。上线效果还没有统计，我已记入待补充；接下来可以把这部分写入母版。”这只有在实际达到条件时才使用。
