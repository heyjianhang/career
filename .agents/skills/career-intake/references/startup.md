# 启动、盘点与空白引导

先沿用本轮已确认的个人工作区。首次安装或同步选择尚未完成时，进入 [career-setup](../../career-setup/SKILL.md)。初始化结果中的 AGENTS.md 与启动说明必须读取；已准备好的工作区无需重新安装。

从个人目录使用 `npm run career --` 调用锁定版本；开发仓库中也可使用该入口，但要显式指定独立工作区。缺 Node/npm 时按 [安装说明](../../../../docs/installation.md) 引导；不要要求普通用户构建源码。每次新会话按 AGENTS 检查远端资料与本地进度，大节点先保存本地再询问同步。

以下 `<工作区>` 替换为本轮实际路径，参数放在子命令之后：

```bash
npm run career -- workspace status --workspace "<工作区>" --json
# initialized:false，或缺少起步文件时，执行：
npm run career -- workspace init --workspace "<工作区>" --json
npm run career -- workspace check --workspace "<工作区>" --json
```

status 只读，返回 next_reads、missing_files、实体数量、validation 和已保存的 presentations。未初始化不创建目录；status 成功表示盘点执行成功，仍须查看 validation.valid。init 返回 created/preserved；check 出错时非零退出，stderr 是带 errors 的 JSON。`completion:not_assessed` 明确表示尚未判断资料是否完整，不能把文件数量或 valid:true 当作已收集完毕。完整命令清单用 `npm run career -- --help --json` 获取。

命令默认从当前目录向上查找 career.json；显式位置给所有 workspace/resume 命令一致传入 `--workspace <目录>`。路径含空格时正确引用，其他工作区文件引用相对于该目录。配置、context 或 resume/maintenance.md 缺失时重跑初始化，只补缺失文件。已有内容保留，配置不兼容时核对原因，不覆盖重建。

先读 context/INDEX、progress、state 和 resume/maintenance.md。新维护清单的“未盘点”并不表示没有经历：核对已有来源、事实文件与母版索引的清单，必要时读取摘要；本轮只深入当前对象，不为了盘点遍历所有原件或代码。

第一次接手时，从请求判断本轮终点。新用户说“帮我整理／完善简历”，默认完整引导到第一份可编辑、可查看的简历；先盘点与研究，再深入经历，不停在内部母版文件。用户只想记录一段经历、只维护母版或直接导出时沿用限定范围。这个范围写入 progress，当前一项和下一问写入 state，续接时不要在每个阶段重新征求启动许可。

盘点后逐步了解目标方向、地区和准备时间，只问会影响本轮采样与安排的未知。按 [简历前调研](../../jd-research/references/pre-resume.md) 进入多岗位研究，并带着待核对经历回来；不要求首次填满求职偏好，不因没有目标职位名称就无法开始。用“先看这些岗位实际需要什么，再把你相关的经历聊清楚”说明目的，不向用户分派 Skill 或表格填报任务。

## 根据已有内容开始

| 情况 | 第一轮动作 |
| --- | --- |
| 已给旧简历或明确材料路径 | 直接读取可读内容，提取经历概览；说明无法读取的部分，然后针对缺口推进 |
| 工作区已有材料但还未整理 | 核对材料清单与来源，先保存明确事实，选择一段经历继续 |
| 正在口述或点名某个项目 | 先接住当前陈述并保存，不绕回完整入门问卷 |
| 工作区确实为空 | 主动说明本轮先维护哪项，以及为什么；提出一个容易回答的起点 |
| 已有事实或母版 | 核对 state 指向的实际记录，续接当前项；陈旧状态根据文件纠正 |

空白开场示例：“我们先来维护基本信息，建立你的履历起点。你可以告诉我希望在简历上使用的姓名，以及目前是在读、在职还是其他状态；我会边聊边保存。也可以直接从一段你熟悉的经历开始。”只问当前不知道的内容，联系方式可以后补。

如果用户已说明想讲一个项目，开场改为：“我们先整理这个项目。先说它要解决什么问题，以及你主要负责什么，后面再逐步补齐过程和成果。”

默认浏览基本信息、教育、任职、项目、技能、语言和证书的维护状态，按已有内容与用户意愿决定顺序。用户明确没有某类经历时标记不适用及依据；未回答的空白保持待维护或暂缓。

基本信息还包括可选照片，按 [个人资料方法](profile.md) 在该主题提醒一次；不在用户正在讲项目时要求上传照片。旧 profile 或清单没有照片记录时，增量补充记录，保留已有正文。

用户能感知的节奏是“说明现在整理什么 → 保存已经知道的部分 → 展示整理后的表述 → 只问下一项关键缺口”。例如已有项目背景和职责、缺时间时，可以说：“我已整理你负责的流程和交付，收益数字先不写。这段项目大致是从哪年哪月做到哪年哪月？”不要重复问材料已有的答案，也不要为了推进自行回答。

## 启动完成

工作区准备好后立即进入具体维护。初始化只说明文件准备情况，不输出“简历已完成”。第一轮应留下一个实际整理对象、已保存内容或明确待回答问题，更新 state 的下一步。
