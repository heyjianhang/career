# 模块与经历的维护状态

`resume/maintenance.md` 是用户和 Agent 共同查看的详细清单，记录模块概览、具体经历、母版同步关系和初期完成里程碑。模板见 [maintenance.md](../templates/maintenance.md)。清单只存状态与引用，履历正文仍在 facts。

## 状态含义

| 状态 | 何时使用 | 下一步 |
| --- | --- | --- |
| 未盘点 | 尚未检查已有内容，包括给旧工作区补清单 | 核对实际文件，不能推断为空或已完成 |
| 待维护 | 已确认该项需要整理，尚未形成有效记录 | 主动解释并邀请开始当前主题 |
| 维护中 | 已保存部分内容，仍有影响表达的缺口 | 展示已知内容，围绕最关键缺口追问 |
| 本轮已整理 | 本条记录满足类型标准，已保存并给用户看过，剩余问题不妨碍当前准确表达 | 衔接母版或下一项；不等于外部证实 |
| 待更新 | 有新事实、纠正或反馈尚未同步到当前内容 | 只重开受影响项并更新 |
| 暂缓 | 用户暂不提供、暂时记不清或决定以后补 | 保留原因和恢复提示，不冒充完成 |
| 不适用 | 用户明确没有该类内容或明确当前范围不包含它 | 记录说明依据；缺失不自动等于不适用 |

模块状态覆盖已知条目，不代表全部职业历史已穷尽。一项已整理、一项维护中的模块仍标维护中；存在未处理变更时标待更新；同模块有暂缓条目时在范围／缺口栏明确列出，不能用概览隐藏它。

## 交互节奏

从当前主题解释开始，先保存用户已说出的部分，再按类型方法补问。给用户展示整理结果后，满足条件即可说明“这一项本轮已经整理好了”，无需逐字段审批。关键矛盾未解决、重要项目仍只有抽象职责或缺具体过程时保持维护中；用户回复有纠正则重新打开相关条目。在“已整理范围／问题 ID”栏写出实际覆盖与未解决项，不以“文件已生成”作为依据。提前生成草稿不自动改变事实状态。

空模块要主动引导，例如：“教育经历还没有整理，我们可以先从最近一段开始。你在哪所学校、学的什么专业？”只在确实未知时问，不要求每个人都有工作、项目、证书等全部模块。

## 母版关系与整体里程碑

每条记录关联已有 master ID 或注明尚未生成。教育、技能、语言、证书可由母版索引直接引用事实 ID，关系记为“索引直接引用”，不额外制造母版条目。关联记录内容变化后标明“待核对展示”，避免把直接引用当作已人工复核。

“初期维护完成”由 resume-master 按其阶段标准记录。事实条目标记已整理不会自动完成整份母版；完成后有新项目仍保留初期日期，将新条目及母版当前状态改为需要维护／更新。

不要复制长篇履历进清单；记录条目太多时只展示本轮和未完成内容，历史条目保持可查。context/progress 保存本轮范围与大阶段，context/state 只保留当前一项与下一问。单条已整理后先核对本轮其他条目，不能直接把资料整理阶段记为完成。
