# 基本信息的维护

## 开始与判断

先读取已有个人资料和原简历，只补未知或变更项。确实为空时说明：“我们先维护简历里的基本信息，确定怎样介绍你；联系方式可以随后补充。”从简历使用姓名、当前状态或用户愿意介绍的背景开始。

## 访谈与专业判断

- 姓名、当前状态、所在城市按用户表述保存；意向城市不写成当前居住地。
- headline 可以暂空，或基于已有身份形成准确短描述；不凭空补职位级别、资历年限。
- 电话、邮箱与作品链接按用户选择记录，不要求为了开始维护就提供全部联系方式，也不补身份证等无关资料。
- 基本资料中的个人介绍保留用户自述与事实背景，成熟的总结表达在母版简介维护。

## 保存

用 [profile 模板](../templates/facts/profile.md)，固定保存到 `resume/facts/profile.md`，沿用 `profile-main` 或已有合法 ID。姓名／城市／联系方式等进入 YAML；背景和补充信息进入正文。按 [落盘步骤](saving.md) 保存来源与问题，维护清单链接该文件。

## 简历照片（可选）

首次维护基本信息，且没有已记录的照片选择时，主动提醒：“附件简历可以带照片。你可以提供一张想使用的头像或证件照，也可以先不放；不影响我们继续整理经历。”这是可选项，不把提供照片设为完成条件。接收图片通过当前对话附件或用户指定文件路径；只有文本输入的问答工具不用于索取图片。

已有明确选定的照片直接复用；多张未选定时只补问使用哪一张，不从聊天头像、网页截图或其他附件中自行挑选。用户说暂时没有则记“暂缓”，明确不要则记“不展示”。“未询问”不等于“不展示”。已提醒且用户未回答时记“已提醒，待选择”，继续其他主题；后续仅在用户提到照片或明确要带照片的输出时补问。

- 将用户选定的原始文件保存到 `resume/assets/profile/<稳定名称>.jpg` 或 `.png`，来源登记到 sources，保留原文件；不替换同名文件来覆盖历史照片。
- 在 `resume/facts/profile.md` 的“简历照片”正文记录：选择状态、是否展示、相对工作区的素材路径、来源 ID、文件 SHA-256；用 `npm run career -- workspace hash --path "<素材相对路径>" --workspace "<工作区>" --json` 读取 data.sha256，不能用文件名代替摘要。用户要求偏移裁切时再记录横／纵位置（0–100，默认居中）。照片是素材引用，不写成个人经历或母版正文。
- 当前成果页接受 PNG/JPEG，单张不超过 5 MiB。超限或其他格式先保留原件并说明需要转换，不把用户未要求的修图、换脸或美化当作整理步骤。
- 用户换照片时新增素材引用，保留旧文件，标记需要重新生成成果页；已有 HTML/PDF 不自动改变。

维护清单的“简历照片（可选）”行只记状态和 profile 引用：已选且素材已保存可记“本轮已整理”；用户暂缓记“暂缓”；明确不展示可记“不适用”，附其选择依据。旧清单缺这一行时仅补此行，不重建整份清单。照片选择写在 profile，详细路径不再复制到状态清单。

## 本轮已整理与后续更新

简历使用姓名或明确选择的展示称呼、当前身份背景已有依据；用户希望保留的信息已整理，未知或不愿提供的字段有明确记录，且已展示给用户，即可标记本轮已整理。没有回答的关键身份信息保持维护中；联系方式暂缓不阻塞其他经历。

换城市、联系方式或当前状态时更新原记录。母版索引直接引用 profile；复核组合展示，简介中出现旧状态时同步调整，保留私人字段不直接对外展示的选择。

## 个人网页与作品链接（可选）

维护基本信息时可以连同照片简短提醒：“如果有个人网站、作品集或代码主页，也可以一起放进简历；没有就先不放。”用户已提供链接就保存，不重复询问；暂缓不阻塞生成。保存到 profile 的 links，每项为 `{label, url}`，保留完整 HTTP(S) 地址和用户希望展示的名称。未写协议时先核对完整地址，不能随意拼接站点或项目路径。

区分可对外展示的个人主页与仅供核对的来源链接。用户提供作为简历内容的链接可用于输出；明确只作参考或不展示的链接记在来源／正文，不能自动公开。生成附件时把选定网页映射到 contacts 的可选 url；无链接不创建占位。薪资、意向城市和行业属于求职目标，不作为个人资料收集的完成条件。
