# 公司池与岗位交接

公司池是用户工作区中的普通研究文件，不是个人履历事实、投递记录或新增的公司工商数据库。默认路径 `research/companies/`；不在源码仓库保存用户资料。旧工具无法在页面显示时仍可读写原文并告知限制，不声称旧版本已支持界面入口。

## 文件归属

| 文件 | 保存内容 |
| --- | --- |
| `INDEX.md` | 稳定公司 ID、名称、公司记录链接及用户关注状态；简短索引，不复制完整分析 |
| `companies/<公司ID>.md` | 主体和品牌、业务与地点证据、个人相关性、招聘线索、用户笔记、后续岗位链接、结论变更记录 |
| `searches/<日期-主题>.md` | 本轮方向、城市、约束、使用的经历／简历及读取时间、检索范围、筛选取舍、候选公司链接与关键限制 |
| `sources/` | 实际取得且需要留存的材料；记录来源和时间，引用已有 JD 或附件时不维护第二份可变原文 |

每次先读 INDEX 和同一公司已有记录。公司 ID 可用 `company-<稳定短名>`，建立后不因改展示名而更换；跨城市和不同批次复用同一主体。集团与子公司分别记录联系，无法确定同名主体时暂存搜索报告中的待核实项，不强行合并。发现重复时保留旧 ID 到新记录的说明和已有链接，不能删除用户备注。

用户关注状态可为“未选择、关注、暂缓、不再关注”；首次结果为未选择，只有用户决定才改状态。研究建议可为“优先了解、进一步核实、暂不优先”，附本轮依据。招聘状态独立维护：找到相关岗位／仅找到招聘入口／暂未找到相关岗位／确认已关闭，标明所查城市、方向与检索时间。一份关闭的岗位不能代表整家公司停止招聘。

## 一份公司记录的可读结构

正文组织可调整，以下字段确保另一位 Agent 能接着做；没有证据的内容明确未知，不填充套话。

```markdown
# 公司展示名

公司 ID：company-example
用户关注：未选择
最近核实：实际日期

## 公司与地点
品牌、法人、官网；注册地／总部与具体团队或岗位地点分开。
业务与行业位置，称号记录层级、批次、公示或认定状态和证据编号。

## 为什么值得了解
所依据的用户方向、经历或简历；直接相关／能力可迁移／依据不足。
研究优先级及原因，新增门槛与关键未知，不猜匹配分。

## 招聘线索
岗位名称或招聘入口、实际工作地点、来源、核实日期和状态。
已建岗位写实际 ID 与相对文件链接，没有 JD 就保留线索。

## 证据与限制
证据编号、主张、来源标题／机构、链接、发布与检索时间、限制。

## 用户笔记与后续
用户原话、待核实问题、结论变化和原因。
```

索引、搜索报告和公司记录用相对 Markdown 链接互相引用；各公司文件是该公司的主记录，搜索报告只写本轮筛选取舍。保存前重新读取修改目标，合并用户手改；如工具支持摘要比较则使用，冲突后重读。当前普通研究文件没有专用 CLI 事务，多 Agent 不同时修改同一个公司池。

## 接入后续能力

- **深入公司研究**：将实际公司路径、已确认主体、用户问题和证据时间交给 career-company；无岗位时合并进公司原记录，有岗位时保留总体来源并在 analysis/company.md 写该岗位所需判断。后续事实变化标明日期，不让不同岗位中的旧报告假装自动更新。
- **转成岗位**：只有用户选定或已授权筛选入库，且取得真实公司／职位／JD 时才调用 career-board。先 `board overview --json` 去重，读取 `opportunity schema --json`，按真实输入 `opportunity add`／`opportunity write --path job.md`，已有文件遵守 read／if-match 协议。不虚构 `company promote` 等尚不存在的命令。
- **回写关联**：只有建卡和 JD 保存回执成功后，才在公司记录写实际岗位 ID 与 `../../../opportunities/<岗位ID>/job.md` 相对链接。失败保留待入库，重试先查是否已经建卡；不标记已投递。我的资料中的该链接可打开对应岗位。公司原记录继续保留，一家公司可以关联多个岗位。
- **岗位与简历**：career-board 推荐并按用户选择绑定具体简历，career-match 才分析该 JD 与版本；career-outreach 在准备投递材料时调用。简历仍由 resume-tailor 保存，研究不改事实或已投递快照。
- **方向研究**：多份真实 JD 交给 jd-research，研究保存在 research/jd/；公司名单不计为 JD 样本。目标公司报告引用研究位置，避免复制第二份需求台账。

本轮结束在 context/INDEX.md 登记当前搜索报告，state 记录当前公司 ID、实际产物、下一步和待用户决定；范围变化时更新 progress，保留未完成的经历访谈断点。`history save` 和用户已有授权下的同步包含 research/companies/；任意其他 research 目录不会因此全部纳入。凭据、Cookie 和会话链接不保存。文件已保存、本地版本已记录、远端同步成功分别按实际回执说明。
