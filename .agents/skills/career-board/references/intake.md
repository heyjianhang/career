# JD 入库与分析编排

按用户本轮范围执行。用户说“帮我登记并看看这个岗位”时，走入库、公司分析和可进行的简历匹配；明确只保存 JD 时保存即止，不擅自扩展。不要要求用户先完成整套履历访谈。

## 1. 先把原文留下

先 overview/list 查同平台岗位 ID、来源链接和已知卡片，避免重复。同公司不同岗位分别建卡。已有卡片先读 context；原文变化保留来源和时间，不覆盖用户补充。

已有 JD 正文就直接保存；链接使用当前可用采集／联网工具读取，无法访问时保留链接并请用户粘贴正文。截图识别保留原图、注明转写性质和模糊处，不补写职责。只知道链接而缺公司／职位等创建必需信息时，先问缺失的必要信息，不编造公司名。

以当前 `opportunity schema --json` 为准，`opportunity add --input <临时.json> --json` 建卡，`opportunity write --id <ID> --path job.md --input <临时.md> --json` 保存 JD。已有文档更新先 read 并带 `--if-match`。字段中的来源、时间和原文彼此可追溯；card.md 管元数据，首页直接读 job.md。不要生成“待确认／下一步”概况模板，不把分析加进 JD。原文入库完成后即可查看，后续研究失败不会使原文丢失。

## 2. 独立研究公司

调用 [career-company](../../career-company/SKILL.md)，传岗位 ID、已知主体、JD、用户关注点和现有报告。没有企查查配置时说明可在设置中配置，同时用可用联网工具继续；网络也不可用就留下基于现有材料的有限判断。不要把配置服务当强制入库前提。

## 3. 确定用于匹配的简历

- 已绑定：读取该简历实际正文与摘要，交给 [career-match](../../career-match/SKILL.md)。不能为了高分换成别的版本。
- 未绑定但用户已明确指定版本：核对 ID 与内容，按本轮授权关联，再分析。
- 未绑定且用户没有选版本：先 `resume list --json`，按方向筛选并 read 最相关的一两份，解释推荐哪个、为什么；问“建议用「某版」投这个岗位，要帮你关联并做匹配分析吗？”即使只有一份，也不静默绑定。已有明确授权不重复问。
- 用户想先比较：调用 career-match 对候选分别做标明版本的分析，保存候选报告，暂不写成当前绑定版的结果。
- 没有简历：公司分析和 JD 入库仍可完成，告知“还没有可关联的简历”，询问是否从已有材料整理一版；用户需要时再进入 career-intake / resume-tailor，不强制开始访谈。

绑定用 `opportunity resume --id <岗位ID> --resume <简历ID> --if-match <最新卡片摘要> --json`。不复制第二份可变简历到岗位目录。新版本、正文修改或 JD 改变后，旧匹配报告需要复核，不能沿用旧分数假装最新。

## 4. 有 subagent 时如何委派

有工具且任务确有独立部分时，可以让 subagent 读取相应 Skill。JD 入库后，公司分析与**已确定版本**的匹配分析可并行；简历未定时先做公司分析和候选建议，不提前生成某版的最终匹配。无 subagent 工具就由当前 Agent 依次执行，同样保存证据和结果。

委派包包含：工作区绝对路径、岗位 ID、本轮问题／范围、对应 SKILL.md 路径、JD 路径和摘要、已确认主体、用户已知偏好；匹配任务另附简历 ID／路径／摘要。只传需要的材料，不传服务密钥。明确仅返回报告草稿、引用证据、输入版本、关键未知和完成范围。

默认子 Agent 只读材料并返回草稿，主 Agent 统一与用户沟通、重新核对输入版本并顺序保存；创建卡片、绑定简历、更新任务、recommendation 与同步均由主 Agent 负责。即使输出文件不同，也不要同时调用带工作区写锁的 CLI。不以“已派发”当完成；失败只报告失败部分，成功部分正常留存。

子 Agent 提出的问题由主 Agent 去重，只问当前最关键的一两个。保存完再完成相应任务；等待绑定时记 waiting_user，不能写成匹配完成。任务本来很短时无需为了分工制造待办。

## 5. 完成这一轮

确认 JD、公司分析、匹配报告各自实际保存的位置，执行 `board check --json`。简短告知已完成什么、哪一步等用户决定；不用把所有内部流程再念一遍。需要续接时在 context/state.md 记岗位 ID、产物和断点。

能力匹配不等于公司价值；综合推荐需按 [评分方法](job-evaluation.md) 核对条件、用户目标与证据覆盖。无需评分时直接给有依据的建议，不强制写 recommendation 或 next_action。用户星级、阶段、投递和联系招聘方均按用户实际决定，分析完成不自动推进。
