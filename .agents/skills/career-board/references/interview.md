# 面试协作：准备、模拟和实际记录

开始准备、考前诊断、出题或评价回答前，读取[考核设计与评价](interview-assessment.md)。按“岗位任务—期望行为—具体问题—回答证据—反馈重练”执行；文件操作不能替代这些专业判断。[完整案例](worked-example.md)演示如何从空泛回答追到可评价的证据。

先读岗位 context、JD、关联简历、已有分析及指定轮次 context。只加载当前需要的材料；没有真实安排也能练习，写入 `interviews/general/`，不创建虚构的一面或二面。命令及路径按 [career-board](../SKILL.md) 和 [CLI](cli.md)。

## 先判断用户要什么

| 用户目标 | 交付 | 不必先做 |
| --- | --- | --- |
| 准备某一轮 | 围绕实际缺口的准备材料 | 一次完整模拟 |
| 现在练一练 | 一问一答的模拟与可执行反馈 | 填完准备模板 |
| 刚面完，帮我记录 | 实际问题、回答、反馈与待跟进 | 补做准备／模拟 |

已明确轮次、形式、时长或重点时复用；未知且影响准备才问。不要一次询问所有安排，也不要把用户不记得的问题补造出来。

## 准备：从要求与证据选重点

按真实岗位判断这一轮可能考查什么，并把“根据 JD 推测”与“招聘方已说明”分开。选最相关的几段经历，整理背景、本人行动、关键选择和实际结果；每段能回到事实来源，不撰写不存在的故事。

项目管理侧重范围、优先级、依赖、变更、协调和验收的实际事件；技术侧重方案边界、取舍、故障与验证；业务岗位侧重判断、执行和反馈。对当前最弱的证据准备追问，而不是堆一百道通用题。可补用户向面试官核实的团队／业务问题。

写入本轮 `preparation.md`；已有内容增量更新。尚未确认的案例细节在事实层补充，不能把模拟中的优化建议当作经历。

## 模拟：根据回答继续，不预先代答

明确本次侧重点和可用时间（用户已说则直接使用）。一次只提出一个问题，等用户回答后，根据遗漏、矛盾或有价值细节追问。未收到回答不模拟一段“用户回答”接着往下演。

观察事实具体性、个人与团队归属、逻辑、决策依据和问题相关性。例如只说“我推动各部门上线”，追问一次真实分歧和本人处理方式；只有工具名则问为何采用及如何验证。反馈引用实际回答片段，指出一个最值得改进的点和一个可以重答的问题，不用无依据的总分。

用户要提示可以给组织方法；提供示范时标明示范，并仅用已确认事实。用户要结束就保存已进行部分，未答题记录未练，不把它写成整场完成。

每次练习独立保存到 simulations，内容保留题目、真实回答或准确摘要、关键追问、反馈和下次练习点。标记模拟及所用资料日期；多次练习不覆盖。模拟表现不是招聘方评价，不改变真实面试状态或履历成果。

## 真实面试后：先记录，再复盘

先接住用户记得的内容，逐步补充实际问了什么、本人如何回答、对方明确反馈和下一步安排；不要求全部记得。不确定的原话标作转述，Agent 对成败原因的解释标作假设。

通过 interview save 更新真实轮次 record.md，保留旧内容与最新摘要。招聘方没有给结果时保持未知；某轮已完成不等于岗位未通过或已获 Offer。复盘建议链接可修改的准备材料或需补充的事实，下次 Agent 能看到哪些练过、哪些还没问清。
