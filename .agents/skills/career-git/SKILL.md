# 个人资料的版本保存与同步

用户可直接用侧栏云同步中的更新、同步和自动同步开关；Agent 调用同一套 CLI。用户只需说明选择和缺少的信息。管理当前 career 个人工作区；先核对 `career.json`、用户已有回答和实际 Git 状态，不重复问账号、地址或已选的保存方式。

## 按状态进入

在工作区使用 `npm run career -- <命令> --json`，先 `doctor`；Git 已安装时用 `sync overview` 检查当前目录。返回 GIT_NOT_INITIALIZED 是初始化入口，不是失败后让用户自行处理。若属于父目录仓库或已有其他分支，按错误处理，不能混入那个仓库。

| 当前情况 | 要读取并执行的流程 |
| --- | --- |
| 尚未确定是否同步 | 只问本机保存或自己的 GitHub 私人仓库；已有选择不重复问 |
| 用户选择同步，当前目录未跟踪／还没有远程 | [首次连接](references/first-sync.md)：逐步取得账号状态、仓库地址和缺失提交身份，完成首次保存与上传 |
| 仅本机、第一次需要保存版本 | [首次连接的本地版本步骤](references/first-sync.md#建立本地版本)：不要求 GitHub 或 gh，完成后返回当前任务 |
| 已连接，新会话、保存节点或用户要求同步 | [日常提交与同步](references/daily-sync.md) |
| 新电脑或用户给出已有资料仓库 | [换机恢复](references/restore.md) |

用户选择仅本机时执行 `sync local`。已选择 local 后不每轮询问远程；connected 在开始工作时检查远端，读取最新进度后再继续。

## 始终保持的规则

- 个人资料使用独立 `main`，不为每轮任务新建分支。现有不同分支或仓库历史需先核对，CLI 不静默重命名或覆盖。
- `history save` 仅保存本地；`sync update` 保存后更新、不上传；`sync run` 保存、合并并上传。优先调用这三个能力。用户要求上传当前工作且范围清楚时，这一请求已授权必要的本地保存，不额外重复确认。
- 新连接先说明将同步当前目录中的资料、来源、照片、简历和进度，以及依赖、生成文件、凭据的排除范围。用户已经选择同步并提供私人目标时，继续完成该次连接和首次上传；缺少目标、资料范围有新增疑问时只澄清缺口。
- 后续重要节点默认询问一次是否上传；本轮已有授权或用户明确设置了持续授权则沿用，并记录范围。用户在本机开启自动同步时遵从开关，不逐次问上传；普通小改动不连续打断用户。
- 提交身份只按已有配置或用户提供的姓名、邮箱设置在当前仓库。不猜隐私邮箱，不改全局 Git 配置。
- 默认使用 career CLI 的受管范围和校验，不使用 `git add .` 把目录内所有文件提交。`.gitignore` 无法自动排除已跟踪文件；异常文件先核对。
- 只接入当前用户可写的 GitHub 私人仓库。账号登录由官方流程完成，密码、令牌和验证码不进入对话或资料文件。
- 无变化不创建空提交；不强推、不清空修改、不改写已同步历史。分叉保留双方记录，事实冲突只询问需要用户判断的部分。

## 完成后

记录实际本地提交、远程状态和未完成原因。`saved:true` 才代表新建了本地版本；`synced:true` 才代表本次上传成功。网络或登录失败时保留文件和本地版本，说明远端未核对／未上传，允许继续不依赖远端的任务。

首次准备结束返回工作区 AGENTS 的任务路由，衔接经历收集或用户已经提出的任务，不停在“Git 配好了”。
